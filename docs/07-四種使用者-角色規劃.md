# 四種使用者：學生、家長、老師、校方其他

> 使用者 2026-10-23 指定：**平台至少要讓四種人各自用得起來**。
> 現況只有五級（SUPER_ADMIN／ADMIN 資訊管理員／TEACHER／STUDENT／未登入），**缺家長，也缺「校方其他」**。

## 一、目標角色模型（六級＋未登入）

| 角色 | 中文 | Level | 誰 | 核心需求 |
|---|---|---|---|---|
| `SUPER_ADMIN` | 最高權限 | 6 | 本人 | 全部 |
| `ADMIN` | 資訊管理員 | 5 | 資訊組 | 帳號、權限、審計、內容治理 |
| `STAFF` | **校方其他（職員）** | 4 | 校務處、圖書館、輔導室 | 發公告、看失物與認領、排菜單、匯出報名；**不需要改別人的帳號** |
| `TEACHER` | 老師 | 3 | 任教老師 | 開活動、看成績統計、審認領、發公告 |
| `PARENT` | **家長** | 2 | 學生家長 | 只看**自己子女**的：報名、失物（自己發的）、公告；可代子女報名／取消 |
| `STUDENT` | 學生 | 1 | 全校學生 | 四大模組的日常使用 |
| （未登入） | 訪客 | 0 | — | 只讀公告／活動／菜單／失物列表（不含聯絡方式） |

## 二、家長要看什麼（決定了資料模型）

家長不是「另一個學生帳號」，而是**綁定關係**：

```
User(PARENT) ── ParentLink(guardianId, studentId, relation, verifiedAt) ── User(STUDENT)
```

| 畫面 | 家長看到 | 注意 |
|---|---|---|
| 首頁 | 「我的子女」卡片（1–3 位），點進去切換 | 多子女要能切換 |
| 活動 | 子女的報名／候補狀態，可代為報名／取消 | 名額與候補規則不變，只是操作者不同 |
| 失物 | 子女發布的失物、子女提出的認領 | 不顯示其他學生的聯絡方式 |
| 公告 | 全部（含校曆） | 與學生相同 |
| 菜單 | 全部＋子女的評分紀錄（唯讀） | 不顯示其他學生評分 |
| 老師／校方功能 | **完全看不到** | 後端 403，不只是 UI 隱藏 |

**綁定方式（不做自助註冊，避免亂綁）**：由 `ADMIN`／`STAFF` 在後台建立家長帳號並指定子女（學生編號或姓名＋班別），
或由老師核發「邀請碼」，家長用邀請碼綁定。**第一期先做後台指定**，邀請碼列後續。

## 三、「校方其他」與老師的差別

| 能力 | TEACHER | STAFF |
|---|---|---|
| 讀公告／活動／菜單／失物 | ✅ | ✅ |
| 建立活動 | ✅ | ❌（校務處通常不辦活動） |
| 看自己活動的報名統計 | ✅ | ❌ |
| 審核認領 | ✅ | ✅（圖書館／校務處常處理失物） |
| 發公告 | ✅ | ✅ |
| 排菜單 | ❌ | ✅（校務處訂餐） |
| 匯出報名名單 | ❌（只有自己的活動） | ✅（全部） |
| 管理使用者 | ❌ | ❌ |

> ⚠️ **規格與程式有落差（2026-10-25 記）**：上面這張表是規格（使用者指定「校方其他」要能發公告、審認領）；程式實作（`src/lib/permissions.ts`，v0.12.2）只給 STAFF「排菜單＋匯出」，發公告與審認領仍是 403，後台也只開「菜單」「名單」兩頁。要按規格補能力，得同時改矩陣、e2e（現有測試斷言 STAFF 發公告 403）與三份文件 —— 已列進 `docs/夜間進度.md` 隊列第 12 項，等使用者選邊。

## 四、實作分階段（每一階段都要能單獨驗收）

| 階段 | 內容 | 需要 migration | 驗收 |
|---|---|---|---|
| P1 | 新增 `STAFF`、`PARENT` 到 `Role` enum；權限矩陣加 `menu:manage`（STAFF）等；不影響現有測試 | 是（enum） | 舊測試全綠；`GET /admin/permissions` 多兩列 |
| P2 | `ParentLink` 表＋後台「家長」分頁（建立家長、綁定子女、解除） | 是 | e2e：綁定後家長可查子女報名；未綁定 403 |
| P3 | 家長端首頁「我的子女」＋切換；活動代報名／取消 | 否 | 模擬器實測切換兩位子女 |
| P4 | 家長只看子女資料的權限過濾（後端一律以 `guardianId` 反查，不信前端傳的 id） | 否 | e2e：家長 A 查不到子女 B 的資料（403/404） |
| P5 | 邀請碼綁定（`ParentInvite`，一次性、有期限） | 是 | e2e：過期碼被拒、重複用被拒 |

> 鐵律：**家長的每一支查詢都必須在後端用「綁定關係」過濾**，不能只在 UI 隱藏；這是這類平台最常見的資料外洩點。
