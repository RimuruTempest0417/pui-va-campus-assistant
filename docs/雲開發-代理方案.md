# 雲開發代理方案（W-18，**後備方案**）

> **2026-10-23 狀態：降為後備。** 實測雲開發環境長時間載入不完、極不穩定，考試交付不使用這條路；
> 程式保留、文件保留，等環境穩定或老師要求正式上架時再啟用。預設仍走 `TRANSPORT: 'https'` 直連 Vercel。

> 目的：讓**正式版／教育版**小程序不用 ICP 備案域名也能呼叫現有後端。
> 建立：2026-10-23｜狀態：程式已寫好並在本機驗證，**尚未部署**（等教育版 appid）

## 為什麼需要它

微信正式版的 `wx.request` 只能打**已 ICP 備案**的域名；`*.vercel.app` 不可能備案。
但**雲函數呼叫是伺服器對伺服器**，不走小程序的合法域名校驗 —— 所以：

```
小程序 ──wx.cloud.callFunction──► 雲函數 apiProxy ──HTTPS──► Vercel API ──► Neon
        （微信內部通道，不需備案）              （伺服器端，不受域名限制）
```

後端完全不用改，權限仍然由後端 JWT + capability 判斷。

## 實測：測試號確定不能用雲開發

```
wechatide -c hermes cloud_env_list --project .
→ {"ok":false,"message":"Test account cannot use cloud services"}
   原始錯誤：{"ret":-601059,"errmsg":"测试号不能使用云服务"}
```

**結論：雲開發必須是正式（或教育版）appid**。這也是為什麼有教育版之後才走得通。

## 已完成的程式

| 檔案 | 作用 |
|---|---|
| `cloudfunctions/apiProxy/index.js` | 雲函數：只接受 `/api/v1/` 路徑、只允許 GET/POST/PATCH/DELETE、轉發 JWT、15 秒逾時、統一錯誤格式 |
| `cloudfunctions/apiProxy/package.json` | 無外部依賴（純 `https`），部署快 |
| `config/config.js` | `TRANSPORT: 'https'｜'cloud'`、`CLOUD_FUNCTION`、`CLOUD_ENV` |
| `utils/request.js` | `TRANSPORT==='cloud'` 時改走 `wx.cloud.callFunction`，錯誤碼與 https 通道一致 |
| `scripts/use-appid.mjs` | 同一資料夾切換 appid（測試號 ↔ 教育版） |
| `config/appids.json` | appid 對照表（教育版 appid 待填） |

## 本機驗證（直接呼叫雲函數的 `main`）

```
GET  /api/v1/notices?limit=1     → 200，回「颱風期間停課安排」
POST /api/v1/admin/login         → 200 SUPER_ADMIN
GET  /admin/users（白名單外）      → 400 BAD_PATH
GET  /api/v1/admin/users（帶 JWT）→ 200，回 3 個帳號
```

## 教育版下來後的四步

1. `node scripts/use-appid.mjs edu`（先填 `config/appids.json` 的 appid）
2. 微信公眾平台 → 開發 → 雲開發 → 開通（免費額度足夠學校項目）
3. `wechatide -c hermes cloud_fn_deploy --project . --name apiProxy`（雲函數部署）
4. 改 `config/config.js` 的 `TRANSPORT: 'cloud'`，重新編譯 → 正式版也能跑

## 限制（誠實寫清楚）

- 雲開發免費額度有**呼叫次數與資源限制**，大量併發（例如全校同時報名）要留意
- 每次請求多一跳，實測大約 +80～150ms
- 圖片上傳（COS 直傳）也需要備案域名 → 走雲開發時應改用**雲存儲**
- 雲函數與 Vercel 任一掛掉都會影響請求，要保留「直連 HTTPS」這條路（`TRANSPORT: 'https'`）

## 另一條路（互補，不衝突）

如果教育版能用**學校已備案的域名**（例如 `api.puiva.edu.mo`），那就直接用 `TRANSPORT: 'https'` 打自己的網域，不必經雲函數 —— 兩條路都保留，改一個字就切換。
