# v0.130.0 — 全校搜尋補「我的借閱／我的借用」（W-111）

> 2026-11-08｜前端 v0.130.0｜後端 v0.79.0｜沒有新頁、沒有新表、沒有 migration

## 做什麼

`GET /search` 的類別由 **十二類擴到十四類**，把 W-105（假單／報修）同一個形狀補完：

- **`loan`（我的借閱）**：比對書名／作者／索書號，**只回 `returnedAt = null`**（還沒還的）。`badge` 是 `ACTIVE`／`OVERDUE`（到期日已過就算逾期），`date` 是**應還日**而不是借出日，排序「到期日由近到遠」——搜自己借的書，第一個想知道的就是「哪一本最快到期」。`id` 回 **bookId**（點進去是館藏詳情，那裡才有續借）。
- **`booking`（我的借用）**：比對場地名稱／位置／**用途**，只回 `PENDING` 與 `APPROVED`（已取消與已駁回對「我到底借到了沒有」的答案是「沒有」，列出來只會讓人重看一次被拒的理由）。`badge` 是狀態，`location` 另外給（同學記得的是「三樓」而不是場地編號），`id` 回 **resourceId**。
- 兩類都**只認 JWT 的 `sub`**：不吃 query 上的任何 id，帶別人的 `userId`／`studentId` 結果一樣。家長沒有 `library:borrow`／`resource:book`，訪客更沒有 → **這兩種身分連分組都不出現**（不是回一組空陣列）。
- 前端：搜尋頁 chips 12 → 14（「借閱」「借用」與功課／假單／報修同一組身分），借閱那一列寫「借閱中／已逾期 · 到期 2026/11/19」，借用那一列寫「待審批／已批准 · 時間 · 地點」；`types` 上限 160 → 200（十四個類名加上逗號共 74 字，留餘裕）。
- 使用說明補 1 條 Q&A（學生、老師、職員都看得到；家長與訪客不會看到這兩組，說明也照這樣寫）。
- `docs/openapi.yaml` 的 `/search` `types` 參數同步成十四類。

## 設計取捨

- **為何以「未結束」為界，而不是全部歷史**：借閱歷史在「我的借閱」頁（`/library/loans/mine`）已經完整；搜尋的用途是「什麼快到期／有沒有逾期」。還掉的書不會因此搜不到 —— 書名命中時館藏那一組（`book`）照樣會出現。
- **借用不過濾「已結束的時段」**：搜尋是回憶工具（「上個月借禮堂那次」），只有「已取消／已駁回」才是明確不要的答案，所以狀態是唯一過濾條件，排序由近到遠。
- **id 回 bookId／resourceId 而不是借閱單／借用單 id**：這兩個模組沒有「單筆詳情頁」，而且使用者按進去要的是續借與時段，剛好都在館藏與場地詳情頁。
- **示範層同一組規則**：`services/mock.js` 的 `data.search()` 同步加兩段，示範模式（斷網演示）也搜得到自己的借閱與借用；家長與訪客同樣不出現。
