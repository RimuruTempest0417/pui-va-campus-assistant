# v0.80.0 — W-64 報名截止時間真的生效

## 為什麼做這個

`Event.signupEndAt` 這個欄位**從一開始就在 `schema.prisma` 裡**，`docs/openapi.yaml` 也寫了它，
但全專案 `grep signupEndAt` 只有兩處命中（schema 與文件）—— 後端不讀、前端不看、後台不能填。

結果就是：老師就算設了截止時間，學生照樣報得到名，等於欄位是裝飾。
這是典型的「欄位存在 ≠ 功能可用」，也是這輪自己發掘它的原因（不是新發明，是把已經宣告的東西補完）。

## 做了什麼

| 層 | 改動 |
|---|---|
| 後端 | `src/lib/signup.ts`：行鎖之後、算名額之前檢查 `signupEndAt`，過期回 **422 `SIGNUP_CLOSED`**（連候補都不收）。學生自報與家長代報名走同一支函式，所以兩條路一起生效 |
| 後端 | `POST /admin/events`、`PATCH /admin/events/:id` 收 `signupEndAt`（可傳 `null` 取消截止）；**截止時間必須早於活動開始**，等於也擋（422） |
| 後端 | `GET /events`、`GET /events/:id` 多回 `signupEndAt` 與後端算好的 **`signupClosed`**（前端只顯示、不重算）；`GET /admin/events` 也帶 `signupEndAt` |
| 後端 | 網頁後台「報名名單」的活動下拉多顯示「｜報名截止 2026/10/30」 |
| 前端 | `utils/event.js`：`decorate()` 產生 `signupClosed`、`signupEndText`（示範層沒有旗標時用同一個規則自己算） |
| 前端 | 活動詳情：meta 區多一行「報名截止」；已截止時標籤變「報名已截止」，底部主按鈕變「報名已截止」且不可按（已報名／候補者仍可取消） |
| 前端 | 活動清單：卡片多一個「報名已截止」標籤 |
| 前端 | 後台「活動」分頁新增欄位「報名截止日（選填，格式 2026-10-30）」，選了就設成當天 23:59:59；晚於活動當天會先在前端擋一次 |
| 示範層 | `services/mock.js` 同規則擋下並回 `SIGNUP_CLOSED`；新增示範活動 `e8`「家長日（報名已截止）」讓差別一打開就看得到 |
| 使用說明 | 學生／老師各補一條 Q&A（截止後不能報、後台在哪裡填） |

## 設計取捨

1. **判定只寫一份**：後端 `isSignupClosed()`／`lib/signup.ts` 是唯一的門，前端 `signupClosed` 只是顯示用的投影；示範層則刻意用同一條規則重算，兩邊結論才會一致（示範模式的資料不會有 `signupClosed` 欄位）。
2. **已報名的人不受影響**：截止擋的是「新的報名」，已報名／候補者仍可取消、仍可簽到 —— 否則老師一設截止就把舊紀錄鎖死。
3. **不做「報名開始時間」（`signupStartAt`）**：它同樣是死欄位，但校內活動沒有「幾點才開放報名」的需求，硬做只會多一個沒人用的開關；先留著欄位不動。
4. **截止日以「當天 23:59」為準**：老師填的是日期不是時間，選單一時間還要多一個 picker；用「當天結束」符合「10/30 截止」的直覺。
5. **CSV 批次匯入不含截止欄**：匯入格式維持四欄（標題／開始／名額／地點…），要設截止請在後台單筆改；避免改了範本讓既有 CSV 全部對不上。
