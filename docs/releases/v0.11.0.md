# v0.11.0 — 失物智能匹配 ＋ 修正模式切換顯示（W-9，2026-10-23）

## 1. 新功能：智能匹配

詳情頁新增「**可能是你的東西**」區塊（只在有推薦時出現）：
每筆顯示吻合度百分比、類型、地點，以及「為什麼像」（同分類／地點相近／N 小時內／描述相似）。

權重（前端示範與後端一致）：

| 維度 | 分值 |
|---|---|
| 同分類 | 0.35 |
| 地點相似（pg_trgm > 0.4） | 0.25 × 相似度 |
| 時間差 3 天內 | 0.15 |
| 標題／描述相似（取較高者） | 0.25 × 相似度 |

**閘門**：地點或文字至少要有一項像（place > 0.4 或 text > 0.3），否則不推薦。
原因：只算「同分類 0.35 + 三天內 0.15 = 0.5」會把所有同分類的東西都推出來，那是垃圾推薦。
總分低於 **0.45** 不回傳，最多 5 筆；只配對相反類型（LOST ↔ FOUND），已結束的不參與。

## 2. 修正：切換離線後首頁沒跟著變

`pages/index` 的 `onShow` 原本只更新時鐘欄位，所以從「資料來源」頁切完模式返回，首頁數字還是舊的（**你看到的現象**）。
現在 `onShow` 會比對目前模式與上次載入的模式，**一變就整頁重抓**；沒變才只更新時間。

## 3. 修正：訪客看詳情整頁失敗

`data.me()` 改成容錯後回傳 `null`，但詳情頁仍寫 `me.nickname` → 未登入時 TypeError，整個詳情空白。
改為 `!!(item.author && me && item.author.nickname === me.nickname)`。

## 4. 新增守門：方法對齊檢查

`data.js` 的方法若在 `api.js`／`mock.js` 找不到同名實作，自檢直接 FAIL。
這次就是靠它抓到 `data.matches` ↔ `api.matchItems` 命名不一致（詳情頁推薦永遠是空的）。
