- **日期**：2026-11-07
- **版本**：前端 `v0.101.0`／後端 `v0.55.0`
- **分支**：前端 `develop`（未合 `main`、未上傳微信）

## 這一版做了什麼

放假那天，課表頁原本只看「今天是不是週末」——星期一到五一律顯示當天 7 節課，
學生在重陽節打開只會覺得「這個系統不準」。校曆（公告 ＋ 活動）本來就有放假資料，
所以不另開一張「假日表」，而是把課表接上去：

1. 後端 `GET /timetable/today` 多回兩欄：`dayOff`（`{ source, id, title, reason }` 或 `null`）
   與 `dayOffReason`（給畫面的一句字，非放假時是空字串）。
2. 判定規則（`src/lib/timetable.ts` 的 `findDayOff()`，一支共用）：
   - **① 當天發布的 `kind: CALENDAR` 公告**（老師用公告寫「重陽節假期」就是它），標題即原因；
   - **② 當天壓到上課時段 ≥ 3 小時的全校活動**（`clubId` 為空的活動，例：運動會、全校旅行日）。
     門檻刻意設 3 小時：傍晚的家長會、下午兩小時的講座不該把整天課表關掉。
   - 兩者都沒有 → 照常上課。週末不查（`dayOff` 一律 `null`，避免把週末誤標成「放假」）。
   - 停掉的公告（軟刪除）不列入 —— 老師撤回停課公告就自動恢復正常。
3. 前端：
   - `pages/timetable`：「今天不用上課」下面那行改成寫原因（`重陽節假期（校曆公告）`），
     週末才顯示原本的「週末愉快，星期一見。」
   - 首頁「今日課表」那條副標：放假時直接寫原因，不再只寫四個字。
4. 示範層 `services/mock.js` 用**同一套規則**算（`demoDayOff()`，同一組上課時段與 3 小時門檻），
   不是寫死 `null` —— 否則演示斷網、走示範模式時這個功能永遠看不到。

## 設計取捨

- **不新增「假日」表**：校曆公告與活動已是唯一真相，多一張表等於兩份資料，公告改了假日表不會跟著改。
- **「全校活動」用 `clubId` 為空判定**：目前後台建活動不填社團就是全校活動。社團活動即使一整天也不算停課
  （已在測試與示範層驗過）。
- **不自動連網抓公眾假期**：澳門公眾假期沒有穩定 API，硬接反而多一個會壞的來源；老師發一則校曆公告即可。
- **畫面未親眼驗**：這輪沒有開開發者工具，`pages/timetable` 與首頁的文字變化只驗到資料與邏輯層
  （`check-states`／`check-pages-boot`／資料層），實際觀感等下次開模擬器或 Gary 自己看。
