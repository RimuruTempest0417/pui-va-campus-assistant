# v0.27.2 — API 契約（`docs/openapi.yaml`）重複路徑合併＋契約守門

> 隊列 #11。**小程序程式與後端行為都沒有改**，改的是 API 文件與守門腳本；版號 +1 以維持「版號＝最新 release」的對照。

## 做什麼

- **整檔原本根本無法解析**：`docs/openapi.yaml` 第 277 行是 `items: { : "#/components/schemas/ItemClaim" }`（`$ref` 被吃掉，疑似某次 sed 把 `$ref` 當變數展開）→ 任何 YAML 解析器（含 ruby Psych）都在此行失敗。修成正常的 `$ref` 之後才驗得下去。
- **6 組重複路徑合併**（`/subscriptions`、`/admin/stats`、`/admin/items`、`/admin/events/{id}/signups`、`/admin/events/{id}/signups.csv`、`/admin/menu`）：原本同一路徑寫兩次，YAML 取後者、前面那段操作被靜默丟掉。**每一組都以 `src/routes/*.ts` 的實際實作為準挑一份**，不是無腦留後面那份：
  - `/subscriptions`：留前段（`{templateIds, scene}`，回 `ok/scene/count`）並**補回被吃掉的 `get`**；後段寫的 `{templates: [itemClaimed…]}` 是舊介面，刪。
  - `/admin/menu`：留前段（`{date, mealType, dishIds}` 同日同餐別覆蓋）；後段的批次 `{entries: [...]}` 後端沒有實作，刪。
  - `/admin/stats`：兩段欄位都與後端不符（`dau`／`claimSuccessRate` 根本不存在）→ 依 handler 回傳改成 `users`／`byRole`／`items{open,claimed,added7d}`／`claimsPending`／`events`／`signups{confirmed,waitlist}`／`noticesActive`／`ratings{count,avg}`。
  - `/admin/items`：留後段（有 response schema），補 `pageSize` 參數與「含已下架」說明。
  - 兩支名單端點：留後段（path 參數寫在 path 層級），CSV 補上欄位說明（狀態／候補順位／姓名／年級／班別／openid／報名時間、不含已取消、寫審計）。
- **刪掉 2 條後端不存在的假操作**：`POST /admin/items/{id}/approve`（後端只有 `PATCH /admin/items/:id`，body `{action: REMOVE／RESTORE}`）、`DELETE /items/{id}`（後端只有 `PATCH /items/:id` 改狀態）。文件教人打一支 404 的端點，比沒有文件更糟。
- **`GET /items/matches?itemId=` → `GET /items/{id}/matches`**：後端是 path 參數、回 `{items, minScore}`；頁面 `services/api.js` 本來就照後端寫，錯的只有文件。文件裡另有一份正確的段落，合併後只留那份。
- **`docs/02-資料模型與API.md` 四列同步**：`/admin/items?status=PENDING`（PENDING 不是合法狀態）→ `status=OPEN&page=&pageSize=`；`POST /admin/items/:id/approve` → `PATCH /admin/items/:id`；`/admin/menu` 寫明 body；`/admin/stats` 改成實際欄位。
- **新增 `scripts/check-openapi.mjs`**（重複鍵／可解析／操作數下限，`--parity` 另外與後端路由表對帳），並接進 `scripts/verify-all.mjs` 成為第 2 步（結構 → **API 契約** → 三態 → 資料層 → console）。

## 怎麼驗

- `node scripts/check-openapi.mjs` → **52 條路徑／59 個操作，0 重複鍵**（修正前：6 組重複鍵、且整檔解析失敗）。
- 同一支腳本故意把 `MIN_OPS` 調高 → **exit 1** 並印「操作數 59 低於下限」；對照組還原後 exit 0（確認守門真的會紅，不是印好聽的）。
- `node scripts/check-openapi.mjs --parity` → 文件有、後端沒有：**0 條**（修正前 2 條）；後端有、文件沒有：**25 條**（已列隊列 #18，本輪不動）。
- `node scripts/verify-all.mjs --no-console` → **4 通過／0 失敗**（結構 19 頁 0 警告、API 契約、三態 19 頁、資料層 62/62）。
- ruby `YAML.load_file` 讀回：`paths` 52 條、`/subscriptions` 有 `post`＋`get`、`/admin/stats` 的 8 個欄位鍵齊全、`/admin/menu` 有 `200`／`403`。

## 取捨

- **操作數 61 → 59 是刻意的**：少的 2 條是「文件有、後端根本沒有」的假操作；`/items/matches` 只是併進已經存在的 `/items/{id}/matches` 段落，沒有少記任何真端點。守門下限因此釘在 59，之後只准往上。
- **`--parity` 不列入 exit code**：後端還有 25 條路由沒寫進契約（`/admin/users` 系列、`/admin/audit`、`/reports`、`/health` 等）。把 25 條一次補完要逐支讀 handler 的請求／回應形狀，硬塞進同一輪只會寫出一堆猜的 schema；列成獨立一項（#18）比假裝一致好。
- **只用 ruby 驗解析、沒有引入 YAML 套件**：小程序 repo 沒有 `package.json`／`node_modules`，為了一支守門去裝依賴會把交付包弄髒；macOS 內建 ruby 的 Psych 已足夠，找不到 ruby 時標「未驗」而不是假綠。
