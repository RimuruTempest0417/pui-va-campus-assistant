# v0.89.0 — 測驗倒數與溫習計劃：把「還有幾天」和「先讀哪一科」放在同一頁（2026-11-06）

> 純前端：沒有新後端端點、沒有新 migration（後端維持 **v0.47.0**）
> 任務：W-69（P1）

## 為什麼

考試前的資訊其實早就都在系統裡，只是分在兩個地方：

- **日期**在校曆（公告、活動、學校發布的 ICS），但校曆是一格一格的月視圖，看不到「還有幾天」；
- **強弱**在成績頁，但那裡只有一科一科的原始分數，沒有「現在該先讀哪一科」。

學生真正要做的決定只有一個：**距離下一場考試還有幾天、這幾天先讀哪一科**。這一頁就是把這個決定算出來，
而且**只用站內已有的資料**（校曆＋成績），不接任何外部服務，也沒有任何 AI 生成 —— 排序是一條寫得出來的規則，
每一列都標明理由，學生不同意也看得懂為什麼。

## 設計取捨

- **不新增後端端點**：倒數與溫習都是「既有資料的另一種視圖」。多開一支 `/study` 等於兩份真相 —— 公告改了、校曆改了，那一支不會跟著改。
- **公告日期只在文字明寫時才採用**：公告的 `publishedAt` 常常比考試早兩三週，直接拿來倒數會出現「期中考試時間表 0 天後」這種荒謬結果。寧可少抓，也不要抓錯（誤判的倒數比沒有更糟）。
- **排序一定要說得出理由**：只給名次的話，學生只會覺得「為什麼叫我先讀 100 分的化學」。所以 `why` 是函式回傳的一部分，畫面直接寫「4 天後有這一科的測驗」／「成績偏低」。
- **不做「建議溫習時數」**：那需要題庫、章節與個人學習速度，「平均分 74 → 建議 90 分鐘」是編出來的數字，寧可不做。
- **不做提醒推送**：既有通知中心是「事件驅動」（報名成功、候補轉正），倒數是每天變的，做成推送會變成每天騷擾；先讓學生自己點進來看。
- **不用 emoji**：入口沿用 `pv-icon` 的文件線性圖標（`notices`），天數用字級與顏色分層，不加裝飾。
