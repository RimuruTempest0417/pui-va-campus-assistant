# v0.92.0 — 搜尋多一類：菜單（打「咖喱」就知道哪一天有）（2026-11-06）

> 前端 v0.92.0／後端 v0.50.0；沒有新表、沒有新 migration（`/search` 多一組來源）
> 任務：W-74（P2）

## 為什麼

菜單已經有 2 頁、每週都排，但學生想知道「這星期哪天有咖喱」時，只能一天一天點。
首頁那顆放大鏡已搜公告、活動、失物與轉贈，卻沒有菜單 —— 而「吃什麼」正是校園裡最高頻的問題之一。
這一版把菜單接進同一支搜尋：**一支輸入框、五種東西**。

## 設計取捨

- **`id` 回菜色 id，不回「某天某餐」的 entry id**：前端點下去要的是菜色詳情（評分、營養、歷史），不是「這一天的那一列」。同一道菜在一週出現兩次就會有兩筆結果，各自帶自己的日期 —— 這正是「哪天有」的答案。
- **不建新端點**：菜單本來就有 `/menu` 與 `/dishes`，多開一支 `/search/menu` 等於把「誰看得到」抄第二份。
- **不顯示過去的日期**：與轉贈同一條原則 —— 搜尋結果要能「按進去就有」。
- **菜單與其他類同分時的排序刻意相反**：其他類是「越新越前面」，菜單是「越近越前面」，因為使用者問的是「最近哪天有」。

## 沒做的（刻意）

- **不加「最近吃過」或「依評分排序」**：搜尋只回答「哪裡有」，排序交給菜單頁的熱門榜。
- **不做菜單的類型 chip**（W-75）：搜尋頁目前仍是一支輸入框、五類一起回；等真的覺得吵再加 chip，那是獨立一項。
- **不把菜單接進「最近搜尋」的建議**：最近搜尋只記關鍵字，不記類型。
