## 為什麼

失物、活動、菜單、公告是「看」的功能；圖書館是第一個「有稀缺資源、要排隊、會逾期」的功能，
而這正是這個專案最拿手的三件事的交集：**交易內列鎖**（可借量）、**候補與自動補位**（預約）、**權限分級**（館藏管理只給圖書館職員）。

它也是校內最容易被拿來比較的模組 —— 所以不做展示頁，做的是可以真的借、真的排、真的催的一整套。

## 設計取捨

- **一本書不拆成「每本實體一列」**：校內沒有館藏條碼資料，拆了只會讓登記工作量變 30 倍，借還判斷完全一樣。
- **「已留書」會擋住別人**：剩下的本數若全被 READY 的候補佔住，其他人拿到的是候補而不是借出 —— 只在 UI 提示會被繞過。
- **逾期天數不落庫**（動態算 `dueAt`）：每天要跑一次更新表的設計，換不到任何好處。
- **下架與刪除並存**：下架（`ARCHIVED`）保留歷史但不能借；刪除（`deletedAt`）從前台消失，有書借出中不給刪。
