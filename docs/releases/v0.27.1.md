# v0.27.1 — 一鍵驗收：`scripts/verify-all.mjs`

> 隊列 #10。純工具改動，**小程序程式與後端行為都沒有改**（前端版號 0.27.0 → 0.27.1 只是跟著守門更新）。

## 做什麼

- 新增 `scripts/verify-all.mjs`：一支指令依序跑完四支守門 —— 專案結構（`check-project`）→ 三態一致（`check-states`）→ 資料層（`check-data-layer`）→ console 走查（`check-console`，預設帶 `--warn`，把 warn 也算不通過），最後印固定格式的「通過／失敗／略過」彙總。
- 失敗時直接把該步完整輸出（含行號）貼在該步底下，不必回頭重跑一次才知道錯在哪；`--verbose` 才會印成功那幾步的完整輸出。
- 「開發者工具沒開」與「頁面有錯」分開判定：console 這步先問一次 `check_wechatide_status`，未就緒就標 `⏭️ 略過（未驗）`，彙總再用 ⚠️ 明講「略過等於未驗」，不會假綠；`--strict` 讓略過也算不通過（交付前用）。
- 參數：`--no-console`（CI／只改文件時跑前三項）、`--only project,data`、`--strict`、`--verbose`。

## 怎麼驗

- **全綠**：`node scripts/verify-all.mjs` → **4 通過、0 失敗、0 略過**，共 175.3s（專案結構 19 頁 0 警告／三態 19 頁全過／資料層 **ALL PASS 62/62**／console 走查 19 頁 **0 error、0 warn**，該步 174.9s）。
- **失敗路徑**（故意注入違規）：在 `pages/index/index.wxss` 尾巴加 `.zz-inject { color: #123456; }` → `--only project` 回 **exit 1**，印出 `pages/index/index.wxss:172 寫死色值 #123456`，彙總列 `❌ 專案結構 檢查失敗：1 個錯誤`；`git checkout -- pages/index/index.wxss` 還原後重跑回 **1 通過、exit 0**。
- **略過路徑**：`PATH=/usr/bin:/bin node scripts/verify-all.mjs --only console`（模擬 `wechatide` 不在 PATH）→ `⏭️ 略過（開發者工具未就緒：wechatide 沒有回狀態）`、exit 0；同一條加 `--strict` 回 **exit 1**。
- **計時**：前三項各 0.0–0.1s；console 走查 174.9s（19 頁，含每頁輪詢到 loading=false）。

## 取捨

- 用 `spawnSync` 一支一支跑子程序，不在 verify-all 裡 `import` 各檢查：四支腳本各自有 `process.exit` 與 `root = process.cwd()`，串在同一支會互相污染；子程序也讓「哪一步紅」直接對應到能單獨重跑的指令。
- console 預設帶 `--warn`：夜間驗收標準是 0 error／0 warn，先前 warn 只列出、不影響 exit code，很容易在彙總裡被讀成綠。
- 略過不能算通過，但也不該讓 CI 紅：預設 exit 0 ＋ 明顯的 ⚠️ 提示，`--strict` 才是「要簽名」的門檻。
