# v0.5.3 — 修首頁白屏（scroll-view 高度塌成 0）（2026-10-22）

## 症狀

開發者工具裡整個小程序**白屏／停在啟動**，DevTools console 只有它自己 JSON 編輯器的 i18n warning，沒有任何 JS 錯誤。

## 根因

v0.5.2 把 `.page-scroll` 從 `height: 100vh` 改成 `flex: 1; min-height: 0`（為了讓導航列佔頂部、內容區吃剩下的高度）。
但這個寫法**只有在父層是 flex 容器時才成立**：

- 失物四頁的根都有 `page-root`（`height: 100vh; display: flex; flex-direction: column`）→ 正常
- **首頁的根只有 `class="home"`，不是 flex 容器** → `flex: 1` 被忽略、`scroll-view` 沒有高度 → **高度塌成 0** → 整頁白屏

## 修法

- 首頁根節點改為 `class="home page-root"`
- 新增守門：任何 wxml 只要用了 `.page-scroll`，根節點必須含 `page-root`，否則檢查失敗（已做反向測試：故意移除 → 立刻報錯）

## 驗證

| 項目 | 結果 |
|---|---|
| 結構檢查 | ✅ 7 頁面 / 0 警告；反向測試（移除 page-root）→ ❌ 立即攔下 |
| 首頁內容位置 | `.home__top` top = **94px**（安全區正確） |
| 首頁實際渲染 | 問候語 **402×37px**、宮格 **195×124px**（不是 0，代表真的畫出來了） |
| 資料 | 4 個模組、loading=false |

## 教訓

「改用 flex 撐高度」這種重構，**每一頁的根節點都要一起改**；只要有一頁漏了，症狀是白屏而不是報錯（最難查）。
以後凡是改共用的版面規則，先跑守門腳本，再用元素尺寸驗證「有沒有真的畫出來」，不要只看 data 有沒有載入 —— data 正常但元素高度 0 就是白屏。
