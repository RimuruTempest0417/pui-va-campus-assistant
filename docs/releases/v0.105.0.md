# v0.105.0 — 班級名單可設定：批次分班、按班篩選、完成率分母修正（2026-11-07）

任務：W-86（P1，後端 v0.58.0）

## 做了什麼

- **班級名單可以批次設定**：後端新增 `GET /admin/classes`（每班人數、有沒有課表／功課、未分班人數）
  與 `POST /admin/classes/:className/members`（`{ userIds, action: 'ADD' | 'REMOVE' }`）。
  以前要指定「我們班有哪幾位」只能一個一個改帳號，現在一次勾一批。
- **不建班級表**：班級名單就是 `User.className` 的 groupBy 投影。另開一張名單表會出現
  「名單說 30 人、實際 28 人」的兩份真相，而功課完成率的分母正是讀這一份。
- **班名是三邊聯集**：有學生的班 ＋ 課表裡有的班 ＋ 派過功課的班。後兩者讓老師能把
  「還沒有人註冊」的班先建出來（否則新班永遠不出現在選單裡，也就永遠指派不了）。
- **`GET /admin/users?className=`**：按班級篩選，`__none__` 代表還沒分班的學生。
  這一條同時是兩個前端的篩選來源，不必各自再算一遍。
- **小程序後台「使用者」分頁**：多一列班級 chips（全部／未分班＋人數／各班＋人數），
  按一顆就只顯示那一班；「批次分班」打開後，每一張學生卡上方多一個可點整列的圓圈，
  選好按「加入這一班」或「移出這一班」，確認一律走 `wx.showModal`。
- **網頁後台同一個功能**：使用者分頁多「班級篩選」下拉、「班級」欄位、「班級名單」區塊
  （班名可用 `datalist` 選已存在的班，清單左邊多一欄勾選方框），批次加入／移出送同一支端點。
- **修掉一個真的會算錯的數字**：功課完成率的分母原本是「帶班級的所有帳號」，
  但收件人規則（`lib/homework.ts`）只發給 `STUDENT` —— 老師一旦有班級就被算進分母。
  現在分母也只算學生，跟實際收件人一致。
- **使用說明**補一條 Q&A（怎麼一次把一整班學生設定好班級），並修正完成率那條的措辭
  （「那一班有幾個學生帳號」）。

## 設計取捨

- **`REMOVE` 只清「本來就在這一班」的人**：管理員可能在 A 班畫面勾到別班的人，
  直接 `className = null` 會靜默清空 B 班。現在回 `{ updated, skipped }`，
  沒動到的數量會出現在提示裡（網頁版寫「N 個沒動：本來就不在這一班」）。
- **等級規則沿用帳號管理**：只能調整比自己低的帳號，`SUPER_ADMIN` 永遠不能動。
  管理員不能把另一個管理員搬進班級（同等級 → 403），與「只能管理比自己低」一致。
- **班名正規化**（去頭尾空白、連續空白收成一個）在後端做，不在前端各寫一份；
  `__none__` 這個哨符在寫入端直接擋掉，避免有人真的建出一個叫 `__none__` 的班。
- **不做「各科任課老師只能編自己班」**：能力矩陣目前沒有「班導」這一層，
  硬做會變成前端藏按鈕、後端其實全開。留給後續（需要先有科代表／班導角色）。
