# v0.77.0 — 我的認領（W-60）

前端對應版本 **v0.77.0**；後端 **v0.38.0**。

## 為什麼

失物的前半段早就做完：看到東西 → 提出認領 → 作者或管理員審批 → 通過後的通知。
但**申請人自己沒有地方可以查結果**：通過與否只靠一則訂閱消息，而訂閱消息要使用者當下按過「允許」才會來，
沒按過的人在自己手機上永遠查不到「我那次認領到底通過了沒有」，只能去問學務處。

這一版把最後一段補起來：`我的發布` 頁上方多一個分段控制，切到 **我申請的** 就看得見每一筆申請與處理結果。

## 這一版做了什麼

| 位置 | 改動 |

| `services/data.js` | `myClaims` 走唯一入口（`data ↔ api ↔ mock` 三方對齊） |

| `pages/items/mine/` | 上方 `pv-tabs`：我的發布／我申請的；申請卡片顯示物品標題、狀態膠囊、類型·分類·地點、申請於與處理時間，點列回物品詳情；空狀態說明「可以去詳情頁按我要認領」 |

| `scripts/check-data-layer.mjs` | +5 條：我的認領有資料／帶物品摘要／狀態待審核／時間新到舊／不能認領自己發布的物品 |

## 三個設計取捨

| 決定 | 為什麼 |
|---|---|
| 直接掛在 `pages/items/mine` 用分段控制，不開新頁 | 這是同一個問題的兩面（我貼的／我申請的），開新頁等於多一個入口要維護、也多一個「從哪裡進去」的疑問；首屏可點元素也沒有增加 |
| 後端用 `request.user.sub` 反查，不吃 query 的 id | 這是資料外洩最常見的形狀：前端傳什麼就查什麼。家長端當年也是同一條鐵律 |
| 一筆申請也回「未通過」而不是消失 | 使用者要知道結果。申請被拒後從清單消失，他會以為自己沒送出過，然後再送一次（而 `@@unique(itemId, claimantId)` 會直接擋下） |

## 已知缺口（下一版可做）

- **沒有「已取件」狀態**：認領通過後物品變 `CLAIMED`，但「誰什麼時候來拿走」沒有記錄。要做就得在 `ItemClaim` 加 `pickedUpAt` 與一支核銷端點（職員掃碼／輸碼），比這一版大。
- **申請人看不到自己當初寫的特徵描述**：後端有存 `message`，卡片這一版沒有顯示（欄位已回在 API 裡，加一行就行）。
- **訪客（未登入）進來仍是「載入失敗／請先登入＋重試」**，沒有專門的登入提示畫面 —— 與「我的報名」現況一致，等一起改那一批頁面時再做。
