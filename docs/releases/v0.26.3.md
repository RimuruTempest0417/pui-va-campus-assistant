# v0.26.3 — 19 頁 console 走查（可重跑的版本）＋線上後端漂移診斷（2026-10-24）

## 這一版解決什麼

夜間隊列第 6 項是「19 頁 console 走查（逐頁開、抓 error/warn）」。動手才發現**這件事原本做不到**：
`wechatide get_simulator_console` 在 skill v0.3.11 只回啟動那兩行（`WeChatLib: 3.17.5`、`Lazy code loading is enabled`），
連我們自己在 `automation_evaluate` 裡 `console.error('WALKTEST_MARK')` 的測試字串都抓不到（已實測兩次）。
也就是說，用官方 console 工具做走查會得到**永遠的假綠**。所以這一版先把「看得見 console」這件事做出來，再拿它去走 19 頁。

## 改了什麼

| 檔案 | 改動 |
|---|---|
| `utils/diagnostics.js`（新） | 把 `console.error`／`console.warn` 包一層，寫進 storage `pv_diag`（最多 40 則，帶 `level`／`route`／`at`）。包完仍呼叫原本的 console，DevTools 面板照常看得到；storage 讀寫全部 try/catch，收集器自己壞掉也不會讓頁面掛掉 |

## 走查抓到的真問題（這一版只記錄，不改程式）

線上後端（`pui-va-campus-server.vercel.app`）與資料庫都在漂移：

1. **Neon 正式庫有 4 個 migration 沒套用**：`20261023181135_add_staff_parent_roles`、`20261023221958_client_error_logs`、
   `20261024010000_add_parent_links`、`20261024120000_event_checkin`。實查 `information_schema` 確認 `event_signups` **沒有 `checkedInAt` 欄位**，
   而線上跑的程式會 select 它 → **帶登入 token 打 `GET /events/mine`、`GET /events/:id` 一律 500**（不帶 token 是 200／401，所以很容易漏看）。
   畫面表現就是「我的報名」「活動詳情」進 failed（「服務暫時不可用」），console **不會**紅 —— 這正是走查要多印「內容筆數」的原因。
2. `pages/parent/index` 對 STAFF／學生是 403（設計如此），但畫面呈現成「失敗＋重試」，重試永遠不會成功。

本輪沒有動資料庫（夜間不自動遷移 production）；已列進夜間隊列第 6 項，優先處理。

## 設計取捨

- **只收 error／warn，不收 log**：`console.log` 在頁面裡太雜，收了只會把真正的錯淹掉。
- **不用 `get_simulator_console`**：它回不到執行期輸出（上面已實測），硬用它會讓「0 error」變成假證據。
- **多印一欄「內容筆數」**：console 沒紅 ≠ 頁面畫得出來。線上 API 掛掉時頁面只進 failed 狀態，不會 console.error —— 沒有這一欄，走查就是空綠。
- **框架競態不算失敗**：快速用腳本切頁時框架會印 `routeDone with a webviewId … is not found`（單獨開那一頁重跑 2 次都沒有，已實測）。
  腳本把它列在 `~` 之下但不影響 exit code；白名單只有這一條，其餘 error 一律不通過。
- **automator 偶發斷線要重試**：`timeout waiting for automator response` 是已知的連線抖動，重試 3 次（間隔 900ms）才判定工具層失敗，
  否則十幾頁的走查會被一次抖動整批染紅。
