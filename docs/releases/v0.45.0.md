## 為什麼提醒放在後端而不是小程序排 timer

小程序只有被打開才活著，關掉之後沒有任何東西會執行 —— 「時間到了自動發」本質上需要一個
**一定會跑**的東西。放在後端還順便解決另一件事：同一個活動不必對每個使用者各跑一次判斷，
一次查詢就能對全部正取發完。

## 設計取捨（三條）

1. **不用分散式鎖**：`updateMany where { flag: null }` 先搶旗標再發，兩個排程同時打進來只有一個拿到 `count = 1`。
   代價是「搶到但發送失敗」不重試 —— 提醒遲到比通知重複三次傷害小。
2. **跑晚了不補發**：第一次跑時活動已在 1 小時內 → 只發 1 小時版本，並把 24 小時旗標一起填上，
   不會先收到「明天見」再收到「一小時後」。
3. **候補不發、已開始的活動跳過**：候補沒來是正常的，過期訊息比沒有訊息更糟。
