# v0.50.0 — 登入失敗鎖定與帳號安全（W-41）

> 前端 **v0.50.0**｜後端 **v0.25.0**｜2026-10-25

## 做什麼

**後台帳號密碼連續打錯 5 次，帳號會被鎖 15 分鐘；管理員在看得到「最後登入時間」的同一列按一顆鈕就能解鎖。**

原本後台登入只有「每分鐘 10 次」的 IP 限流 —— 那擋的是同一個 IP 猛打，擋不住有人換 IP 慢慢猜同一組帳號密碼。這一版補上**帳號層級**的鎖定，並把「上次什麼時候登入」顯示出來（帳號被共用的第一個線索）。

- **後端**（v0.25.0）
  - `User` 加 `failedLogins`／`lockedUntil`（migration `20261024230318_login_lockout`）。
  - `POST /admin/login`：密碼錯就累加，**第 5 次錯在後台上鎖 15 分鐘**；鎖定期間**連正確密碼也回 429 `RATE_LIMITED`**，訊息與 IP 限流一致（不透露帳號是否存在、也不說「你被鎖了」）。鎖定到期自動重新計數；密碼正確就清零，避免卡在兩步驗證那關的人被後續嘗試鎖住；成功登入寫 `lastLoginAt`。
  - `GET /admin/users` 多回 `failedLogins`／`lockedUntil` 與**後端算好的 `locked`**（前端不比時間，避免手機與伺服器時鐘不一致時顯示錯）。
  - 新 `POST /admin/users/:id/unlock`：能力 `user:ban`（資訊管理員以上）＋ 等級規則（只能解鎖比自己低的帳號），寫審計 `user.unlock`。
- **小程序後台**（「使用者」分頁）
  - 每列狀態：停用／**已鎖定**（紅 Tag）；帳號那行多「· 已鎖定」，最後登入時間改成跟手機同一時區（原本直接顯示 ISO 字串）。
  - `canManage` 且真的被鎖時，操作列多一顆「解除鎖定」。
- **網頁後台**（`GET /admin`「使用者」分頁）
  - 狀態徽章「已鎖定」＋「解除鎖定」按鈕；最後登入時間改用本地時區顯示（原本直接切 ISO 字串，差 8 小時）。
- **站內使用說明**：管理員 Q&A 多一條「帳號顯示『已鎖定』怎麼辦？」。
- **順手修的兩個真 bug**（同一天出貨，因為都是「畫面顯示到別的字」）
  1. **v0.48.0 後台統計卡片撞 key**：概況分頁的「本週概況／累計／點卡片跳到對應分頁」沿用了 `k100~k102`，把出席名單的「（未設定）／已簽到／未簽到」蓋掉 —— 簽到名單的 Tag 會顯示成「累計」或「點卡片跳到對應分頁」，**console 完全沒有錯**。改用 `k157~k159`。
  2. **登入頁兩步驗證欄位撞 key**：兩步驗證碼的標籤／placeholder 用 `k01`／`k02`，被同一個 `labels()` 後面的「登入／培華校園助手」蓋掉 —— 欄位標籤顯示成「登入」、灰字顯示成「培華校園助手」。改用 `k12`／`k13`。
  3. 設定頁 `labels()` 裡有一組被覆蓋的死 key（`k01~k06` 安全／兩步驗證…），刪掉避免下次又撞。
- **新守門（`check-project.mjs` 第 17 條）**：掃 `pages/`、`components/` 每個 `.js` 的 `data` 與 `labels()` 物件，**同一個物件裡重複的 key 直接判錯**。上面兩個 bug 就是這條會抓到的形狀 —— 編譯不報、runtime 不報，只有畫面文字錯。

## 設計取捨

- **第 5 次錯仍回 401、下一次才 429**：不讓攻擊者知道「剛好第 5 次」這個界線；封鎖訊號出現在下一次嘗試。
- **不存在的帳號不計次**：沒有資料列可寫，也不該為猜測產生垃圾資料；代價是「帳號不存在」與「密碼錯」的回應完全一致（本來就是這個目的）。
- **`locked` 由後端算**：前端只顯示。否則手機時間慢幾分鐘就會出現「明明解鎖了還紅字」。
- **解鎖要 `user:ban` 而不是 `user:assign:teacher`**：解鎖是「安全事件處置」，跟停用同級；老師不該能做。
