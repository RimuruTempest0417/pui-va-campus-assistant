# v0.31.0 — 登入頁改成原生表單、找出「按了沒反應」的真兇（2026-10-25）

## 一、真兇：自動化連線把模擬器的事件管線打斷了

你截圖 Console 裡重複出現：

```
DOMException: Failed to execute 'postMessage' on 'Worker': function(e){var t=this._wxElement; …
 at extensions/worker/asdebug/index.js:3400
```

`asdebug` 是**開發者工具的自動化除錯 worker**（我這邊接上去操作模擬器用的）。
它拋出 `could not be cloned` 之後，Skyline 的 worker 通道就壞了 → **你自己用手點的任何按鈕都不會有反應**，
但我的自動化「直接派發事件」卻仍能成功 —— 所以我才一直測到「登入正常」，你卻一直登不進去。

這是我的操作造成的，不是你的帳號、密碼或後端。**以後我每次用完自動化就立刻 `close_project_window` 斷開**，
不把連線留在你的模擬器上。

## 二、順手把登入頁做成「不可能點不動」

| 改動 | 為什麼 |
|---|---|
| 登入按鈕改成**原生 `<button form-type="submit">`** | 原本用自訂組件 `pv-button`；Skyline 下自訂組件的 `tap` 偶發收不到 |
| 帳密改用 **原生 `<form>` 取值** | 原本靠 `bindinput` 把值寫進 `data`；Skyline 受控 `input` 偶發不同步 → data 裡是空的，登入必失敗 |
| 保留 `bindconfirm` | 打完密碼按鍵盤「完成」即可送出 |
| 錯誤訊息帶錯誤碼 | `帳號或密碼不正確（UNAUTHORIZED）`／`連不到後端：…（NETWORK）`／`嘗試太多次…（RATE_LIMITED）` |
| 按鈕文字隨狀態變 | `登入` → `登入中…` |
