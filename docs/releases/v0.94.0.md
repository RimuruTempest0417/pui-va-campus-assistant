# v0.94.0 — 班級課表：首頁直接寫「下一節在哪間課室」（2026-11-06）

> 前端 v0.94.0／後端 v0.51.0；兩張新表 `class_periods`、`timetable_slots`（1 支 migration，第 31 支）
> 任務：W-73（P1）

## 為什麼

學生每天最常問的兩件事就是「下一節是什麼」和「在哪間課室」。
校曆只有活動與公告，沒有正規課表；而「今天有幾節、什麼時候放學」目前只能看貼在課室後面的紙。

這一版把課表搬進系統，重點是**首頁那一行**：「今日課表 · 數學 · 302（10:30）」——
不必點進去就知道接下來要去哪裡。點進去看整天（正在上的那一節標「現在」），或切「整週」一次看完五天。

## 設計取捨

- **節次時間全校共用一份**：一間學校只有一個時間表；每個班各存一份遲早會出現「3 班第 4 節 10:30、4 班 10:35」的不一致。
- **「現在第幾節」在後端算**：前端算等於把時區與節次規則抄第二份，而且手機時間設錯就會顯示錯的課。`at` 參數讓測試可以餵固定時間。
- **週末回 `schoolDay: false`**：回空白課表會讓人以為「還沒匯入」，說「今天不用上課」才是答案。
- **匯入先檢查、已存在不覆蓋**：與活動／菜單同一套。老師重貼一次匯出檔不該把代課調動蓋回去。
- **首頁用入口列而不是卡片**：一行字就能回答「下一節在哪」，不需要為它多一張卡。

## 沒做的（刻意）

- **不做「調課／代課」流程**：要留「原本誰上哪一節」的歷史，這一版只有現況；要改就重新 upsert 那一格。
- **不在前端提供逐格編輯表單**：一週 40 格用手機點會很痛；實際匯入情境是一份 CSV。單格 API 留給之後的網頁版。
- **不把節次時間做成後台可編輯頁**：預設八節已符合學校時間表；要改再開，先不猜 UI。
- **UI 觀感未親眼驗**：這一輪沒開開發者工具，課表格線與「現在」那條紫線請以真機／模擬器為準。
