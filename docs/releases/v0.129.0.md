## 為什麼

W-109 的訂閱已經把「我的報名／假單／功課截止」放進手機日曆，但三件同樣「只有本人看得到、而且忘記會出事」
的事還在外面：**書什麼時候到期**（忘了還就是罰款）、**星期五下午借了禮堂**（忘了去就是開天窗），
以及沒有一個地方可以調「日曆要看多遠」。圖書館與場地本來就都在庫裡，缺的只是把它們接到同一支輸出。

## 規則（寫進程式也寫進測試）

1. **已歸還的書不出現**：訂閱是提醒「要去還」，書已經在架上就沒有意義。
2. **未批准的借用不出現**：待審批還不保證有場地，寫進日曆只會讓人白跑一趟。
3. **視窗外一律不出現**：`days` 是雙邊界（今天起算），200 天後到期的書不會偷偷塞進來。
4. **只含本人（與綁定子女）**：`userId` 取 JWT 的 `sub`＋`parent_links` 反查，別人的借閱與借用完全不會出現。
5. **`days` 不影響權杖**：日曆 App 已經訂閱的那條網址，換範圍時只要換連結，不必重新產生（舊連結立刻失效是「撤銷」的語意，不該被設定值觸發）。

## 設計取捨

1. **不加新頁、不加新分頁**：設定頁那張卡多一列就夠。這一版的需求是「日曆要有這幾件事」，
   不是「再開一個校曆設定頁」—— 多一頁等於多一塊從沒被真人看過的介面。
2. **天數只給三個值（30／90／180）**：自由輸入只會讓後端每次抓更多資料，而「日曆看多遠」是習慣不是參數。
3. **換天數不換權杖**：權杖的語意是「這台裝置被授權」，範圍是內容參數；把兩件事綁在一起，
   調一次設定就要重新貼一次網址到日曆 App，實際上沒有人會去調。
4. **借閱一本一筆、借用一筆一段**：借書是「那一天到期」的點事件，借場地是「這段時間我要用」的區間事件，
   兩者的 DTEND 語意不同，所以不硬套同一個形狀。
