# v0.124.0 — 全校搜尋補「我的假單／我的報修」（2026-11-07）

## 做了什麼（W-105）

搜尋本來九類（公告／失物／活動／菜單／轉贈／功課／提案／館藏／場地），
但學生打「發燒」「冷氣」這種自己寫過的字，找不到自己送出的假單與報修單 ——
只能回兩個頁面各自翻。這一版把兩類補進搜尋，**沒有新頁面、沒有新表、沒有新端點**。

- 後端 `GET /search` 的 `types` 由九類擴到十二類：新增 `leave`（我的假單）與 `repair`（我的報修）。
- 前端搜尋頁 chips 10 → 12（「假單」「報修」插在功課之後，與功課同一組身分：要登入、家長沒有）。
- 兩類都**跳各自的清單頁**（`pages/leaves/mine`／`pages/repair`），不接 id —— 假單與報修沒有詳情頁。

## 為什麼這兩類的規則跟其他十類不一樣

其他十類是「大家都看得到的內容」，只差在誰有權限看；假單與報修是**個人資料**
（哪天不在校、什麼原因、哪間教室的鎖壞了），所以：

- `studentId`／`reporterId` **一律取 JWT 的 `sub`**，不吃 query 上的任何 id。
  帶別人的 `studentId` 打進來，結果跟自己打的一模一樣（e2e 有一條專門驗這個）。
- 家長沒有 `leave:create`／`repair:create`（家長代子女請假走另一支 `leave:create:child`），
  訪客更沒有 —— 這兩種身分**連分組都不出現**，不是回一組空陣列。
  家長要看的出口是「我的子女 → 假單」，那條走 `parent_links` 反查。
- 老師也不是「看得到全班」：`/search` 只回老師自己送出的那幾筆，
  要看學生的假單請走 `GET /admin/leaves`（那條有自己的能力閘門與班級範圍）。

## 結果長什麼樣

| 類別 | `title` | `badge` | 第二行 |
|---|---|---|---|
| 我的假單 | 「病假 2026/11/09」（跨日寫「2026/11/09–11/10」） | `假別:狀態`（例 `SICK:PENDING`） | 待審批／已批准／已駁回 · 日期 |
| 我的報修 | 「304 室 冷氣」（地點＋器材） | 狀態碼（`PENDING`／`IN_PROGRESS`／`DONE`／`CANCELLED`） | 地點 · 多久以前送出 |

假單與報修單都沒有「標題」欄位，所以 `title` 由後端組一句人看得懂的話；
摘要（`snippet`）取真正命中的那一段（假單的原因／駁回原因，報修的說明／處理備註），
跟其他類「摘要要取自命中的欄位」同一條規則。報修另外帶 `location`，前端那一行才寫得出在哪一間。
