# v0.131.0 — 圖書館逾期清單與匯出（W-112）

> 2026-11-08｜前端 v0.131.0｜後端 v0.80.0｜沒有新頁、沒有新表、沒有 migration

## 做什麼

館員以前只知道「有人逾期」，要知道「誰、哪一本、逾期幾天、哪一班」只能一筆一筆翻借閱紀錄。這一版把逾期的名單變成一支端點與一顆按鈕：

- **`GET /admin/library/overdue`**（能力 `library:manage`）：只列**未歸還且已過應還日**的書，按逾期天數由多到少；每列帶書名／索書號／ISBN、借閱人姓名／年級／班別／**學號（由 `sc:` 帳號抽出純數字）**、借出日、應還日、逾期天數、續借次數。`days`（0–365，預設 0）是門檻：`0` 與 `1` 同義（當天到期不算逾期），`7` 只列逾期滿 7 天以上。分頁 `page`／`limit`（上限 100）。
- 回應另帶 `summary`：`count`（幾筆）／`people`（幾個人）／`worstDays`（最久幾天）／`withinWeek`（未滿 7 天的有幾筆）；`days` 原樣回傳，前端不必自己對照。
- **`GET /admin/library/overdue/export`**：同條件回 UTF-8 BOM 的 CSV（`x-row-count`、`content-disposition`、`cache-control: no-store`），欄位順序固定為「書名／索書號／ISBN／借閱人／學號／年級／班別／借出日期／應還日期／逾期天數／續借次數」，日期用澳門時間（`YYYY-MM-DD HH:mm`）而不是 ISO 的 `T`／`Z`；每次匯出寫一筆 `library.overdue_export` 審計（帶 `days` 與列數）。上限 5000 列。
- **兩支端點共用一支 `overdueRows()`**：篩選、天數計算、排序只有一份。這正是「畫面上 7 筆、匯出的檔案 8 筆」的來源，所以不做第二次查詢。
- 網頁後台「圖書館 → 借閱紀錄」下方多一個「逾期清單（館員催還）」區塊：天數門檻下拉（0／3／7／14／30）＋「載入逾期清單」＋「匯出逾期清單」，摘要一行寫「共 N 筆（M 人）· 最久 X 天 · 未滿 7 天 Y 筆」，切到借閱紀錄時自動載入一次。**小程序不加**（微信不能下載 CSV）。
- `docs/openapi.yaml` 補兩條路徑（204 路徑／248 操作，`--parity` 兩邊 0 落差）。

## 順手修掉的語意錯誤：逾期天數改成澳門日界

`overdueDays()` 原本用**毫秒差**（`floor((now - dueAt) / 一天)`），於是「應還日 11/10 18:00」的書，11/11 下午在系統裡仍然是「逾期 0 天」—— 書明明遲了一天，館員的清單與催還文案卻寫「今天到期」。這一版把它改成**澳門日界**（固定 +08:00 位移後取整，澳門沒有夏令時間）：過了澳門午夜就是逾期 1 天。

這是全站唯一的逾期算法，`/library/loans/mine`、`/admin/library/loans`、續借的 `LOAN_OVERDUE`、催還通知、`/me/export` 一起改用日界，不會出現「清單說 3 天、CSV 說 2 天」。**這是行為變更**（政策變更），既有純函式測試的期望值同步改成日界口徑，並補一條「傍晚到期、隔天下午算 1 天」的案例把舊算法的錯釘住。

## 設計取捨

- **門檻在 JS 篩、不在 SQL**：`days=7` 若寫成 `dueAt < now - 7 天`，遇到「傍晚到期」就會把 6 天的也算進來，與畫面顯示的天數不一致。候選集用 SQL 取（`returnedAt = null` 且 `dueAt < now`），天數與門檻一律用同一支 `overdueDays()`。
- **不新增資料表、不加欄位**：逾期是「借閱列的當下狀態」，存一份 `overdue_days` 只會隔天就過期。
- **CSV 只在網頁後台**：微信小程序不能下載檔案（`wx.openDocument` 不支援 csv），硬做只會得到一個按了沒反應的按鈕。
- **學號只留數字**：`sc:s3201301037` → `3201301037`，沿用 `accountToStudentNo()`；微信帳號（老師）留空字串，不冒充學號。
