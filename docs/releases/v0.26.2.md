- **新增守門 `scripts/check-states.mjs`**：把「每頁該不該有載入中／空狀態／失敗可重試」寫成一張 REQUIRE 表，用 WXML／JS 文字判定，`node scripts/check-states.mjs` 不一致就 exit 1，`--table` 直接印出 Markdown 對照表（release note 那張就是它產的）。新頁面沒登記會直接報「未在 REQUIRE 表登記」，避免以後又靠肉眼。
- **補上真正缺的狀態**（原本是空白畫面或錯誤被偽裝成空資料）：
  - 我的發布／我的報名：`loading: true` 但 WXML 沒有任何載入分支 → 首次進頁是一片空白。補兩張 skeleton（實測 375×78）。
  - 列表與資料頁 11 頁補「載入失敗＋重試」：失物列表／詳情／我的發布、活動列表／詳情／我的報名、公告列表／詳情、菜單週視圖／菜品詳情、校曆。
  - **詳情頁分開 404 與其他錯誤**：原本 catch 一律 `item = null`，斷網時畫面寫「找不到這筆資料，可能已被作者刪除」——把後端掛掉說成資料被刪。現在 `codeOf(e) === 'NOT_FOUND'` 才走「找不到」，其餘走「載入失敗：網路不穩…」＋重試。
  - 後台 `pages/admin/index`：分頁切換期間顯示 skeleton（統計頁原本先畫一排 0，看起來像「後台沒有資料」）；讀取失敗（`hint` 以「讀不到」開頭）統一翻成失敗卡片＋重試，不再只是一行灰字。
- **失敗文案修正**：`utils/errors.js` 的 `NETWORK` 原本是「網路不穩，已改用離線資料」，但預設 `DEMO_MODE: 'off'` 根本沒有離線備援（實測把 API base 指向死端口，畫面卻說已經用離線資料）。改成「網路不穩，請檢查連線後重試」。
- `retry()` 一律 `return this.load()`：原本回傳 undefined，自動化／測試無法等它跑完（實測踩到 `Cannot read properties of undefined (reading 'then')`）。

## 取捨

- **分頁的第二頁失敗不蓋掉已載入的清單**：失物列表只在「畫面本來就沒有東西」時才整塊換失敗卡片（`failed: !this.data.items.length`），其餘維持 toast——否則載入更多失敗會把使用者已看到的內容整頁清掉。
- **後台失敗判定靠 `hint` 前綴**：後台 38 個 catch 大多是可預期的操作錯誤（權限、驗證），硬改成全部 throw 會連帶改壞操作流程；因此約定「讀取類失敗一律寫成 hint『讀不到…』」，`loadTab()` 只把這類翻成失敗卡片。這是頁內約定，沒有型別保證，新分頁要照寫。
- **後台三個清單分頁（失物／活動／使用者）仍無空狀態**：那三頁上方都有建立表單，空清單不會看起來像壞掉，本版沒動；已列進 `docs/進度.md` 隊列下一項，不在這版半做。
- 沒有碰手感（按壓回饋）與版面：這版只補狀態分支與文案。
