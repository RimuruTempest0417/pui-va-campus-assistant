# v0.25.0 — 錯誤日誌：手機上看不到的錯誤，後台看得到（2026-10-24）

## 為什麼

交付給老師之後，問題會變成「學生說按了沒反應」。老師看不到學生的 console，我也看不到，
只能靠轉述猜原因 —— 於是修的是「最有印象的錯」，不是「最常發生的錯」。

這一版讓小程序把自己遇到的錯誤送到後端（`POST /client-errors`），後台多一個「錯誤」分頁，
**按出現次數排序**：第一列就是最吵的那一則。

## 改動（前端）

| 檔案 | 改什麼 |
|---|---|
| `utils/reporter.js`（新） | `reportError(message, stack)`：`wx.request` 直送 `/client-errors`（不經過 `services/data`，避免上報失敗又觸發一次上報）。三條規矩：① 全部 swallow，上報失敗不在畫面上產生第二個錯 ② 同一訊息＋同一頁面這次啟動只送一次、兩則之間至少 1.5 秒（一次崩一整串時只送第一則）③ 離線示範模式不上報（示範資料的錯誤不是真問題） |

| `services/admin.js` | `errors(status)`／`setErrorStatus(id, action)` |
| `pages/admin/index/*` | 第 12 個分頁「錯誤」：待處理數／近 24 小時次數／累計、待處理・已解決切換、每列顯示訊息・頁面・相對時間・次數，一鍵「標記已解決／重新打開」 |

## 本輪順手修掉的真 bug

`utils/date.js` 的 `fromNow()` 只吃毫秒數字（`Number(ts)`），**真 API 回的是 ISO 字串**（`2026-10-24T20:32:49.922Z`）
→ 一律 `NaN`，畫面出現「**NaN 天前**」。這不只是新分頁的問題：失物卡、公告卡的「張貼時間」在真 API 模式下也是同一個坑
（`dateTimeText` 之前修過一次，`fromNow` 漏了）。現在兩種格式都吃，沒有時間就回空字串（不再編一個 1970 年出來）。
實測：模擬器讀真 API 的錯誤列表，`fromNow` 由「NaN 天前」變成「1 分鐘前」。

## 設計取捨

- **不用 `hover-class`、不新增組件**：新分頁全部沿用既有 `pv-card`／`pv-tag`／`pv-button`／`pv-empty` 與 `ui.wxss`，不為一個分頁再造一套樣式。
- **不做「送出測試錯誤」按鈕**：那會往真實錯誤表塞假資料，讓真正的第一列被稀釋。要證明通路活著，用自檢頁的方法（`globalData.reportError`）即可。
- **列表一次讀 50 列**（後端預設 `limit=50`，最大 100）：錯誤種類不會多到需要分頁，超過就是該先修；加入分頁只會讓人往後翻而不修。
- **指紋在後端算**：前端只送訊息與堆疊，避免「同一則錯誤因為多一個字就變兩列」。
