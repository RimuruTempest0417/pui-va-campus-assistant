## 這一版做了什麼

功課頁上線後最常被問的兩件事：**「老師附的那份 PDF 在哪？」** 和 **「這一班是不是越來越不交？」**。
原本兩個都答不出來 —— 內容只能打成一行純文字，完成率只有「今天這一刻」的數字。

1. **附件連結**：`Homework.links Json?`（後端第 34 支 migration）。一項功課最多 5 條，
   只收 `http(s)`；字串或 `{ name, url }` 都收，統一存成 `[{ name, url }]`。
   非 http(s) 回 **422**（不靜默丟掉 —— 丟掉的話老師會以為存進去了）、同一條貼兩次只留一條、
   超過 5 條回 422 而不是默默截斷。
2. **PATCH 的語意**：帶空陣列＝清空附件；**不帶就不動**（與 `detail` 同一個規則）。
   這樣舊版小程序不會因為不認得 `links` 而把既有附件洗掉。
3. **學生端**（`pages/homework`）：每項功課的內容下面多一行一條淡底的可點項目，
   沒填名稱就顯示「附件 1／附件 2」；點一下複製連結並提示（小程序沒有瀏覽器，貼到瀏覽器就能開，
   跟活動附件的做法一致）。出功課的彈層多一格「附件連結（選填）」：一行一條，
   前端先驗格式與條數並當場提示，後端仍會再驗一次（前端不是閘門）。
4. **家長端**：`/parents/me/children/:id/homework` 也回 `links`，家長看得到同一份附件（唯讀）。
5. **完成率趨勢**：`GET /admin/homework` 加 `days`（1–30，預設 7）與 `trend`：
   `{ days, local:{from,to}, average, items:[{date,label,items,done,total,rate}] }`。
   **按「派功課那天」分組**（澳門日界 UTC+8），不是按截止日 —— 截止日集中在一兩天，折線會變一根柱子。
   分母是「當天派了幾項 × 班上幾人」，`average` 是整個窗口的加權完成率；沒有資料的那天 `rate` 與 `average` 回 **null**。
6. **後台趨勢圖**：小程序後台「功課」分頁與網頁後台各一組七根柱（CSS 畫，不引圖表庫），
   柱上寫百分比、柱下寫日期，沒資料的那天是淡灰細線（不是 0%）。換班級篩選時趨勢一起只算那一班。
7. **使用說明**：`pages/help` 補三問 —— 學生「功課附的連結要怎麼開？」、
   老師「怎麼派功課」補附件段落、資訊管理員「怎麼看這一班最近是不是越來越不交功課？」；
   家長那條也補一句「附件點一下會複製連結」。
8. **示範層同步**：`services/mock.js` 用同一套規則（`normalizeHomeworkLinks`／`readHomeworkLinks`），
   示範資料 `hw1` 帶一條附連結，`SEED_VERSION` 15 → 16。

## 設計取捨

- **`links` 存在功課本身，不另開附件表**：與活動附件的分別是「活動附件」可以上傳檔案（COS），
  功課只收連結 —— 一個 Json 欄位就夠，少一張表就少一組 FK 與讀取路徑。
- **驗證寫在路由層的純函式，不散落在各分支**：create／patch／三支讀取共用同一組
  `normalizeLinks`／`readLinks`，示範層再抄同一套規則（示範模式放行 `ftp://` 的話，
  切回真 API 才會被 422 擋下，那個落差本身就是 bug）。
- **趨勢按「派功課那天」而不是截止日**：老師問的是「最近是不是越來越不交」，
  派出去的那天才有可比性；用截止日的話一週的功課常常都壓在同一天，圖上只會有一根柱子。
- **不新增端點**：`GET /admin/homework` 本來就是校務處看功課的地方，加一個 `days` 與一個
  `trend` 欄位比多開一支 `/admin/homework/trend` 便宜（也避免兩支端點的分母算法漂移）。
- **前端柱狀圖用 CSS 不用 canvas／圖表庫**：七根柱用 `height` 就畫得出來，
  引入圖表庫會多 100 KB 以上，還要處理深色模式與 Skyline 相容性。
- **沒有資料的那天回 null 而不是 0**：0% 會被讀成「全班都沒交」，這條規則是既有的
  `rate: null`（班上還沒建帳號）延伸，測試把它釘住。
