# v0.14.0 — 小程序內建後台 ＋ 頭像登入（2026-10-23）

## 為什麼改

原本後台是獨立網頁（`/admin`），要複製網址到電腦瀏覽器打開 —— 對老師來說是多餘的一步，
而且「後台」在首頁是一張很顯眼的卡片，一眼就看得出這是管理系統。
改成：**所有人只有一個入口（右上角頭像）**，登入後有權限就多一個「管理」，而且**管理全部在小程序內完成**。

## 新增頁面

| 頁面 | 內容 |
|---|---|
| `pages/admin/login` | 帳號＋密碼登入（教職員同一組入口）；已登入時顯示目前身分與「登出」 |
| `pages/admin/index` | 六個分頁：**概況／認領／失物／公告／名單／菜單**，全部在小程序內操作 |

| 分頁 | 能做什麼 |
|---|---|
| 概況 | 使用者數、待認領、待審認領、正取／候補、有效公告、近 7 天新增、評分數與平均＋登出 |
| 認領 | 一筆一列，直接「通過／拒絕」（通過後物品自動轉已認領） |
| 失物 | 依狀態篩選，可下架／恢復（軟刪除） |
| 公告 | 標題／內容／一般·校曆·緊急／置頂 → 發布（緊急需 ADMIN 以上） |
| 名單 | 選活動看正取與候補，一鍵**複製名單**（小程序不能下載 CSV，複製後貼到 Excel） |
| 菜單 | 日期＋餐別＋菜名（逗號分隔）→ 同名沿用、新名建立、當天同餐別覆蓋 |

## 入口

- 首頁**右上角頭像**可點：
  - 已登入且 `role >= TEACHER` → 直接進管理頁
  - 其他（含未登入）→ 登入頁
- 首頁頁尾不再有「教職員登入」這類字樣（不暴露管理系統的存在）

## 權限

前端只做「顯示判斷」（老師只看到公告分頁），真正的權限在後端能力矩陣：
`stats:read`／`item:review`／`item:moderate`／`event:export`／`menu:manage` 都只給 ADMIN 以上。

## 驗證（模擬器實測）

| 情境 | 結果 |
|---|---|
| `Rimuru` / `rimurutempest` 在小程序內登入 | `role=SUPER_ADMIN`、token 201 字、**自動跳轉管理頁** |
| 管理頁概況 | 使用者 **1**、待認領 **5**、分頁 `stats` |
| 失物分頁 | 5 筆（第一筆「藍色保溫瓶（有貼紙）」） |
| 名單分頁 | 活動 4 個、選中活動後載入名單 |
| 排菜單 | 「2026-10-24 已排入 1 道菜」 |
| 發公告 | 「已發布：驗證用公告」，後端 `GET /notices` 查得到 |
| 登出後點頭像 | 進 **登入頁**（不是管理頁） |
| 結構檢查 | 16 頁面 0 警告 |

> 測試期間產生的示範菜色與公告已刪除。

## 帳號整理

資料庫的測試帳號（`dev-admin`／`dev-teacher`／`dev-super-admin`／開發用 openid）**全部刪除**，
只保留最高權限：**帳號 `Rimuru`／密碼 `rimurutempest`**（`SUPER_ADMIN`）。詳見後端 v0.5.1。
