# v0.107.0 — 校園提案與連署：學生提建議、同學連署、校方回覆（2026-11-07）

任務：W-88（前端 v0.107.0／後端 v0.60.0）

## 為什麼做這一項

老師的評分看重「與培華中學相關、貼近校園生活、有創新」。前十一項功能都在解決「辦事」（借書、借場地、請假、交功課），
缺的是**學生參與校政**這一塊：想建議圖書館延長開放、課室加掛鐘、小賣部加熱食，目前只能口頭講，
講完就散了，没人知道有多少人同意、校方有沒有處理。

所以這一版加的是「提案 → 連署 → 校方回覆」的完整閉環：學生寫下建議，同學連署到門檻，
校方在後台回覆並改狀態（處理中／已列入計劃／已完成／暫不採納），提案人與所有連署人都會收到通知。

## 做了什麼

### 後端（v0.60.0）

- **兩張新表**（第 35 支 migration）：`proposals`（標題、內容、分類、狀態、連署數、門檻、回覆、版本、軟刪除）、
  `proposal_supports`（`@@unique([proposalId, userId])`）。
- **9 支端點**：
  - `GET /proposals`（訪客可看；`status`／`category`／`q`／`sort`／`scope` 篩選，回 `counts` 與 `goal`）
  - `GET /proposals/:id`（含回覆、前 12 位連署人、`canEdit`／`canReply`／`canModerate`）
  - `POST /proposals`（作者自動算第一位連署人）、`PATCH /proposals/:id`（作者、只有 OPEN、帶 `version`）
  - `POST /proposals/:id/support`、`DELETE /proposals/:id/support`
  - `DELETE /proposals/:id`（作者撤回／校方下架，軟刪除）
  - `GET /admin/proposals`（清單＋`counts`／`categories`／`stats`）、`GET /admin/proposals/:id`、
    `POST /admin/proposals/:id/reply`（回覆＋改狀態，通知提案人與所有連署人）
- **票數只信唯一鍵**：一人一票由 `@@unique([proposalId, userId])` 保證，重複按回 `already: true` 而不是 500；
  加票用 `increment` 而不是「讀出來加一」（四個請求同時按，票數等於連署列數，不是三次讀-加-寫）。
- **達標只通知校方一次**：`reachedAt` 是「已通知」旗標，用 `updateMany({ where: { reachedAt: null } })`
  決定誰負責發通知 —— 同一秒多人連署也只會有一輪通知。
- **權限**：新增五個能力 —— `proposal:read`（含 GUEST）、`proposal:create`／`proposal:support`（學生以上）、
  `proposal:reply`／`proposal:moderate`（校內職員以上，ADMIN 顯式帶上才涵蓋職員）。**家長只能讀、不能連署**
  （家長不是校內成員）；老師可以提可以連署，但不能回覆（回覆是校方行政窗口的事）。
- **回收桶接上提案**：`/admin/trash?type=proposal`、還原、永久刪除（先清 `proposal_supports` 再刪提案）。
  撤回與下架都寫審計（`proposal.withdraw`／`proposal.moderate`），回收桶的「誰刪的」回推得到。
- **校方已接手就不能自己撤回**：狀態離開 OPEN 之後作者撤回回 409「要下架請找校方」，
  避免連署人一覺醒來發現提案不見了。

### 前端

- **三個新頁面（第 43–45 頁）**：
  - `pages/proposals/list`：分段「全部提案／我參與的」＋狀態 chips（全部／收集中／處理中／已完成／不採納）＋
    「最新↔最多連署」切換；每一列是分類單字徽章（設／學／活／餐／其）＋標題＋作者與時間＋連署進度條。
  - `pages/proposals/detail`：標題、分類、狀態、連署進度（N / 門檻）、連署人暱稱、校方回覆區；
    底部按鈕由「誰在看＋目前狀態」推導（登入／連署支持／已連署 · 取消／修改內容／已結案），
    作者在 OPEN 時另有「撤回」，校方另有「下架」。
  - `pages/proposals/create`：分類 chips＋標題＋內容；同一頁支援「修改自己的提案」（帶 `?id=`）。
- **首頁第八條入口列**：「校園提案」，副標直接寫「4 個提案 · 2 個等你連署」；新畫一個燈泡線性圖標
  （圓形燈身＋底座兩條＋左右射線，CSS 畫的，沒有 emoji）。
- **後台第 23 個分頁「提案」**（小程序）＋**網頁後台第 20 個分頁**：狀態 chips、全校統計（幾個提案／幾人次連署／
  幾個達門檻）、分類件數、每列「回覆」（展開回覆框＋四種狀態）與「下架」。兩套後台功能一致。
- 使用說明四個身分各補一條：訪客「看得到嗎」、學生「怎麼提建議」、校內職員「在哪裡回覆」、資訊管理員「統計與下架」。
- `docs/openapi.yaml` 補 10 個操作 ＋ `Proposal` schema。

## 抓到的問題（邊做邊修）

- **`trash.ts` 的計數被我改成「只算目前篩的那一類」，`tests/e2e/trash.test.ts` 立刻紅**：
  後台那行「公告 X 筆、失物 Y 筆…」不管篩哪一類都要正確，所以四個總數一律照算。
- **YAML 的 plain scalar 不能含有冒號**：`description: …（proposal:moderate）…` 讓整份 `openapi.yaml`
  寫入失敗（工具直接拒絕），加引號才過 —— 這種錯 `check-openapi` 看不到，因為檔案根本沒被寫進去。
- **`patch` 覆蓋了首頁功課那一列的內容**：old_string 抓到「圖標＋標題＋副標＋箭頭」，new_string 只以箭頭開頭，
  結果功課列變成只剩一個箭頭。發現方式是把改動後的區塊讀回來（`sed -n`）而不是只看 diff 成功。

## 設計取捨

- **不另開「我的提案」頁**：列表頁上方的分段就有「我參與的」（後端 `scope=supported`），
  少一頁也少一個要維護的三態畫面。
- **作者自動算第一票**：畫面上從 1 / 20 起算，不然新提案永遠是 0，看起來像壞掉；
  代價是「提案人不能取消自己那一票」，要收回就用撤回。
- **不通知「有人連署了」給提案人**：一個熱門提案會吵死人；只在校方回覆與達門檻時通知。
- **門檻寫在資料列上（`goal`）而不是寫死程式**：以後要改成 15 人或依分類不同，不必改邏輯；
  已建立的提案各自記住自己的門檻。
- **家長只能讀**：連署是校內成員的意見表達，家長已可透過假單與轉贈參與，不需要再多一條表態管道。
