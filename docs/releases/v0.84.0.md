# v0.84.0 — 家校通登入的四個收尾：對應正確、學號乾淨、同步不再超時（2026-11-05）

> 後端 **v0.43.0**（`pui-va-campus-server`）

## 為什麼

v0.83.0 讓家長「登入就看到子女」，但用 Gary 的真實 `pv` 帳號跑完整條鏈之後，留下四個對不上的地方：

1. **回應契約不一致**：`POST /auth/school` 回 `children` 卻沒有 `linkedChildren`，前端只能自己數陣列。
2. **自動對應的親子關係分不出來源**：`parent_links.createdBy` 是 null，和「管理員人工綁定」長得一樣，後台無法判斷。
3. **學號被存成帳號原樣**：`SchoolLink.studentNo` 是 `pv3201301037`，成績頁顯示「已連結 · pv3201301037」，家長會以為自己學號打錯。
4. **同步 44.5 秒、只差 15 秒就撞 Vercel 60 秒上限**，而且回報 `attendance: 129` 與資料庫實際 **43 天**對不上。

還有上一輪的過度設計要收：曾用「家校通首頁列出的學號」建多筆 `parent_links`，那會生出不存在的親子關係。

## 設計取捨（為什麼這樣做）

- **去重放在寫入前，不是寫入後再數**：唯一鍵是「學生＋日期」與「學生＋學年＋學段＋科目＋類型＋日期」，同一筆 upsert 兩次不會多一列，但會讓「同步了 129 筆」這種回報與畫面數字對不上 —— 使用者看到 43，後端說 129，兩邊都對但信任度歸零。
- **考勤每學年只抓一次**：這是本輪唯一「少抓」的改動，依據是實測 129 ＝ 43 × 3 且唯一鍵去重後剛好 43 天。若學校哪天開始真的按學段切資料，會少抓第二、三學段（可再由 `yearTerms` 指定重抓），但換來的是同步時間從 44.5 秒掉到預算內。
- **部分成功優於整支失敗**：Vercel 的 60 秒是硬上限，超過就是 504 且前端什麼都拿不到。28 秒預算 ＋ `partial` 讓已抓到的資料一定落地。

## 沒做的／要講清楚

- **實際同步時間要再用真實帳號量一次**：本輪把上游請求從 8 支降到 6 支（login／yearTerms／成績 ×3／考勤 ×1），但學校站的延遲我這邊量不到；下次用 `pv` 帳號同步時請留意是否還有 40 秒以上。
- 若學校真的按學段回傳不同的考勤資料，第二、三學段這版不會抓（見上面的取捨）。
- 手感與版面（新增的那行說明、partial 彈窗）仍需你用手指看一次；自動化只驗到資料與狀態。
