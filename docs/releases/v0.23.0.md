## 設計取捨

1. **代報名走後端同一支 `lib/signup.ts`，不另寫一套**：家長端若自己算名額，遲早會跟學生端不一致
   （例如滿額判定、候補順序）。抽成一支之後，兩條路由的差別只剩「有沒有先過綁定閘門」。
2. **前端的門只做提示，真正的門在後端**：`assertParent()`（role 必須是 PARENT）＋ `resolveChild()`（`parent_links` 必須有這對），
   未綁定一律 403 且訊息與「查無此人」相同（不變成學號探測器）。前端不自己判斷「這是不是我的孩子」。
3. **能力矩陣新增 `event:signup:child`**：`PARENT` 有；`ADMIN`／`SUPER_ADMIN` 也標了，但那只是為了
   「上級必含下級」的單調性測試（家長端路由仍限 `role === 'PARENT'`，管理員打進去一樣 403）。
4. **首頁只放切換與三個數字，代報名放下一頁**：首頁可點元素要 ≤ 6 個，把「報名／取消」整套搬上首頁會把第一屏擠爆。
5. **示範層也照同一套規則**（`signupCore(id, userId)`），交付給老師時切離線示範，家長端一樣能切換子女、代報名、取消。
