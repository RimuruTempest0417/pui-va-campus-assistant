# v0.69.0 — W-53 第二階段：小程序後台也能補登成績與出缺席

## 這一版做了什麼

v0.68.0 把「補登」做成了後端能力與網頁後台，但老師要補一筆還得開電腦。
這一版把同一件事搬進**小程序內建後台**（`pages/admin/index` 新分頁「成績」），
老師在手機上就能找學生、看到既有的成績與出缺席、補一筆、刪掉補錯的那筆。

**小程序後台（`pages/admin/index`）**

- 新分頁「成績」：老師（TEACHER）、校內職員（STAFF）、管理員以上都看得到；學生與家長沒有後台入口，本來就看不到。
- 三段式，與網頁後台同一套順序：
  1. **找學生**：輸入學號／姓名／班別查詢；**一進分頁就先列最近 20 位**，老師不必先打字。
  2. **補登成績**：科目、類型、分數、學年、學段（三顆 chip）、日期（原生日期選擇器）。
  3. **補登出缺席**：日期＋上午／下午各一組狀態 chip（正常／遲到／缺席／請假）＋備註。
- 既有的紀錄用 inset grouped 一張卡＋髮絲線；每列右側標「手動／同步」，**只有手動的才有刪除鈕**（同步的是學校系統的真相，刪不掉）。
- **學年／學段沿用該生最近一筆**：補下一科不用重打；出缺席直接沿用同一組（與網頁後台一致）。
- 刪除一律走原生 `wx.showModal` 確認（不用自製兩段式）。
- 分數留空＝`null`（不是 0）；後端「這筆是家校通同步的資料」的原文會直接顯示在 toast，老師才知道要改同步而不是重打。

**後端**：這一版沒有改動（仍 v0.30.4）。七支端點與 `school:manage` 能力是 v0.68.0 就有的，這版只是把呼叫端補上。

## 設計取捨

1. **不新增頁面，做成後台的一個分頁**：Gary 的定案是「後台在小程序內」，補登屬於同一類操作；開新頁等於多一條入口要維護，而且老師會找不到。
2. **一進分頁就先列 20 位學生**：只靠搜尋的話，手機上要先知道學號才能開始；先列出來，老師點一下就好。
3. **學年／學段是全後台共用一組**（不是每筆各一組）：同一批補登通常同一段考，沿用最省事；這也是網頁後台的做法，兩邊語意一致。
4. **刪除只給手動資料**：與後端規則對齊，不是只把按鈕藏起來（後端也會擋，回 422）。
5. 刻意**不做**在手機上「改同步資料」：那是學校系統的真相，改了下次同步還是會被蓋掉。
