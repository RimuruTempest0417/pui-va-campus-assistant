# v0.3.0 — 請求層與示範模式（2026-10-22）

四個模組的共同地基。做完這一版，**沒有後端也能完整操作**，有後端則自動走真 API。

## 新增

| 檔案 | 作用 |
|---|---|
| `config/config.js` | 唯一開關檔：`API_BASE_URL`、`DEMO_MODE`（`auto` / `on` / `off`）、逾時與重試 |
| `utils/request.js` | 封裝 `wx.request`：注入 JWT、8s 逾時、網路錯誤重試 1 次、錯誤正規化 |
| `utils/errors.js` | 後端錯誤碼 → 使用者看得懂的一句話；區分「網路類」與「必須讓使用者看到」的錯誤 |
| `services/api.js` | 對照 `docs/openapi.yaml` 的真實端點 |
| `services/mock.js` | 示範資料層：失物 4 筆、活動 3 個、菜單一週、公告 3 則；寫入持久化到 storage |
| `services/data.js` | **唯一入口**：頁面只 require 這支；`auto` 模式下後端不可用時自動落回示範資料並記 `console.warn` |
| `pages/dev/api-check` | 開發期自我檢查頁（9 項，畫面顯示 ALL PASS） |
| `scripts/check-data-layer.mjs` | Node 版自我檢查（12 項），**CI 也跑**，不需要開發者工具 |

## 這一版抓到的真 bug

- `pages/dev/api-check/index.js` 的 `require` 少一層（`../../services` → 應為 `../../../services`）→ 頁面模組載入失敗、automator 連線一起掛掉（`timeout waiting for automator response`）。修法：相對路徑按層數算清楚，並加上「所有頁面的 require 目標是否存在」的檢查腳本。

## 已知限制

- 程式化 tap **打不到自訂組件內部**（selector 只看得到宿主標籤），所以按鈕手感只能真人驗
- 示範模式的資料存在 `wx.setStorage`，換裝置就重置（這是刻意的：交付時永遠是乾淨狀態）
- 尚未接圖片上傳與訂閱消息（W-8、W-11）
