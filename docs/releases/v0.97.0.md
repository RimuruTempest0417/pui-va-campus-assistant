# v0.97.0 — 通知中心補齊：功課逾期、圖書館催還進得了通知匣（2026-11-06）

任務：W-78（前端 v0.97.0／後端 v0.53.0）

## 這一版在回答什麼問題

「系統會主動告訴我什麼事？」這句話在演示現場說得出口，才算真的有通知功能。
上一版的通知中心只有四類（活動提醒、認領結果、失物相似、有人想要你的轉贈），
而**每天最會忘記的兩件事**——功課什麼時候交、圖書館的書什麼時候還——完全不會通知。
這一版把這兩條補進 `notifications`，並順手發現一個線上真的沒在跑的排程。

|---|---|---|
| 功課到期前／逾期 | ❌ **完全沒有**（功課模組從來沒寫過通知） | 新增 `src/lib/homework.ts` 的 `remindHomeworkDue()`：24 小時內到期、已逾期（回看 3 天），只發給**這一班還沒打勾**的學生 |
| 圖書館到期與預約到書 | ⚠️ **程式有、排程沒有**：`remindDueLoans()` 寫好了、網頁後台有「催還」按鈕，但 `vercel.json` 的 crons 只有活動提醒 → 線上永遠不會自動催還 | 補 `POST/GET /cron/daily` 並在 `vercel.json` 加第二條 cron（每天 02:00 UTC），催還與功課提醒一起跑 |
| 請假審批結果 | ✅ 已有（`notifyLeave`：申請人＋學生本人都收，駁回附原因） | 只補 e2e 斷言，不動程式 |

## 改了什麼

- 後端新增 `src/lib/homework.ts`：
  - 兩個階段：`功課快到截止：<科目>`（24 小時內）／`功課已逾期：<科目>`（逾期幾天寫在內文）。
  - 收件人＝`className` 相符且 `role = STUDENT`、**沒有 HomeworkDone 那一列**的人；已打勾、別班、老師收回（`deletedAt`）的一律不發。
  - 去重窗口是**澳門時區的當天**（`macauDayStart()`）：Vercel 跑在 UTC，用 `setHours(0,0,0,0)` 會在澳門早上 8 點換日，同一天會被發兩次。
  - 逾期最多回看 3 天 —— 再舊的功課不是「提醒」而是「催交」，不該每天塞一則。
- 後端 `src/routes/cron.ts`：新增 `GET/POST /cron/homework-reminders`（可單獨重跑）與 `GET/POST /cron/daily`（催還＋功課提醒，兩個任務各自 try/catch，回應列出兩邊結果與 `errors`）。
- 後端 `vercel.json`：crons 由 1 條變 2 條（`/cron/reminders` 01:00 UTC、`/cron/daily` 02:00 UTC）。Vercel Hobby 上限就是 2 條，所以「一天一次」的雜項收成一支，不是漏做。
- 後端 `src/lib/inapp.ts`：`NotifyKind` 多一個 `HOMEWORK`（`notifications.kind` 是 VarChar，**沒有新表、沒有 migration**）。
- 前端 `pages/notifications/index.js`：`KIND_KEYS` 多一組 `HOMEWORK → 功課`（原本會落到「系統」，看不出是哪一類）。
- 前端 `pages/help/index.js`：學生分頁多一條 Q「功課快到截止時，系統會提醒我嗎？」＋A（兩個階段的文案、去重規則、哪些情況不吵你）。
- `docs/交付給老師.md`：新增 Q5，附一張「系統會主動通知學生什麼」的八類對照表（給老師演示時直接照著講）。
- `docs/openapi.yaml`：補 `/cron/homework-reminders`、`/cron/daily` 兩條路徑（含 GET 與 POST），parity 兩邊 0 落差。

## 設計取捨（答辯會被問的）

- **只通知學生，不通知家長**：家長要看「小孩有幾樣沒交」是首頁摘要那張卡（W-79），每天再發一封「你小孩的功課沒交」只是同一件事講兩次；而且家長帳號與學生帳號是不同 User，兩邊都發等於一個人被吵兩次。
- **去重放在「每人每日每則每階段」**：不用在 Homework 上加 `remindSentAt` 旗標 —— 那個粒度是「整班」，只要有一個人補交，旗標就已經被別人用掉，剩下沒交的人從此收不到提醒。
- **不加新表、不加 migration**：通知本身就是一張表，重複判斷用「同一天、同標題、同內文」查一次，比為了去重多開一張 `homework_reminder_log` 便宜。
- **`/cron/daily` 而不是把功課塞進 `/cron/reminders`**：活動提醒一天可能跑多次（1 小時前那一階段），功課提醒一天一次就夠；混在一起會讓同一個端點的語意變成「跑幾次就提醒幾次」。

## 順手修好的線上問題（不屬於 W-78 的程式，但它讓 W-78 等於沒做）

驗這一版時打線上端點，`/api/v1/cron/daily` 回的是 **503 `CRON_DISABLED`** 而不是 404：
路由部署上去了，但**伺服器根本沒有 `CRON_SECRET`**。往上追發現兩邊都沒設：

- Vercel 專案 9 個環境變數裡沒有 `CRON_SECRET` → 四支 cron 端點在線上永遠回 503；
- `.github/workflows/reminders.yml` 每 30 分鐘跑一次，但 repo 沒有 Actions secret 時走的是「略過不紅燈」那條分支 → 每次都成功、每次都什麼都沒發。

也就是說**活動提醒與圖書館催還從來沒有在線上自動跑過**，`last_status` 一直是 success，這件事只有實際 curl 才看得出來。
處置：產生一組新的共享密鑰，同時寫進 Vercel 專案環境變數（production／preview／development）與 GitHub Actions secret，重新部署後驗收：

| 檢查 | 結果 |
|---|---|
| `curl -o /dev/null -w '%{http_code}' /api/v1/cron/daily` | **401**（改之前是 503） |
| `curl ... /api/v1/cron/reminders` | **401**（改之前是 503） |
| 帶 `Authorization: Bearer <secret>` POST `/cron/daily` | **200**，`elapsedMs 918`、`library {checked:0}`、`homework {checked:0,sent:0}`、`errors []` |
| 帶密鑰 POST `/cron/reminders` | **200**，`checked 0`（線上目前沒有 24 小時內的活動） |
| 手動觸發 GitHub Actions `reminders.yml` | `completed / success`（這次真的打到端點，不是跳過分支） |

密鑰本身沒有寫進任何 repo、文件或對話；維運做法與「503／401／200 各代表什麼」寫在後端 `docs/運維-自動化帳號.md`。
