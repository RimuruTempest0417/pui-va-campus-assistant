# v0.32.0 — 登入頁改用 WebView 渲染，破解教育版「按了卡在登入中」（2026-10-24）

## 問題現象（教育版實測）

按下登入後按鈕一直停在「登入中…」，畫面完全沒有反應；Console 不斷出現：

```
DOMException: Failed to execute 'postMessage' on 'Worker': function(e){var t=this._wxElement; …
 at extensions/worker/asdebug/index.js:3400
 at Object.triggerWorkerEvent
```

## 判斷

`asdebug` 是 **Skyline（glass-easel）的 AppService worker 除錯通道**。教育版那套開發者工具版本較舊，
在序列化事件／資料時把函式塞進 `postMessage` → 結構化複製失敗 → 整個 worker 通訊斷掉。
後果不只是報錯：**頁面的 setData 不再更新、觸控事件也不再派發**，所以按鈕永遠停在「登入中…」、再點也沒反應。
這也解釋了為什麼我這邊自動化測都正常（直接派發事件、不經 worker），你手動點卻一定失敗。

## 解法（三層保險）

| 層 | 做法 |
|---|---|
| 渲染層 | **登入頁改用 WebView 渲染**（`pages/admin/login/index.json` 加 `"renderer": "webview"`），其他 18 頁維持 Skyline。登入是關鍵路徑，不該被渲染引擎的實驗性通道綁住 |
| 使用者回饋 | 登入失敗改用 **原生 `wx.showModal`**（不走頁面渲染），即使畫面層異常也看得到原因 |
| 防卡死 | 加 **15 秒看門狗**：時間內沒有結果就自動解除送出狀態並提示逾時；`onShow` 也會重置，永遠不會卡在「登入中…」 |

## 附帶修好：教育版同步沒刪舊檔

`scripts/sync-edu.mjs` 原本只複製、不刪除 → `docs/夜間進度.md` 改名後，教育版仍留著舊檔（使用者發現）。
現在同步完會**清掉來源已沒有的檔案**（保留兩邊各自的 `project.config.json`／`project.private.config.json`），
本輪就順手清掉了教育版殘留的 `docs/夜間進度.md` 與重複的 `docs/01-藍圖與競賽對標.md`。
