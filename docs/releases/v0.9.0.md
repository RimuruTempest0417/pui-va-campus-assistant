# v0.9.0 — 與後端對齊＋文件同步（2026-10-22）

這一版沒有新頁面，做的是「讓前端、後端、文件三邊說同一件事」。

## 1. API 路徑對齊實作

| 前端原本呼叫 | 後端實際 | 處理 |
|---|---|---|
| `GET /menu` | `GET /menu/week` | `services/api.js` 改路徑，並把 `{ offset }` 轉成 `weekOffset` |
| `GET /items/{id}`、`/items/mine`、`PATCH /items/{id}` | 原本缺 | 後端已補（v0.2.0） |

## 2. `docs/openapi.yaml` 與程式碼對齊（5 處）

| 契約原本 | 改成 | 原因 |
|---|---|---|
| `/items/{id}/claims/{claimId}/review`（POST，`approve: bool`） | `/claims/{id}`（PATCH，`action: APPROVE\|REJECT`） | 與實作一致，body 更好擴充（`note`） |
| `/menu`（`week` / `date` 參數） | `/menu/week`（`weekStart` / `weekOffset`） | 週次用「週一日期或偏移」比 ISO 週直觀，前端已在用 |
| `/uploads/policy`（`scope`，回 `url`） | `/uploads/signature`（`purpose`，回 `policy`/`signature`/`host`） | COS POST policy 的實際欄位 |
| `/notices/{id}/read` | `/notices/read-all` | 實作是「打開詳情即已讀」＋「全部已讀」 |
| （缺） | 新增 `/categories` | 失物分類清單 |

YAML 以 Ruby 的 `YAML.load_file` 驗證可解析。
