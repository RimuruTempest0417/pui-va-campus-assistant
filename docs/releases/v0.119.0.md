# v0.119.0 — 菜單評分統計進兩套後台（2026-11-07）

任務：W-101（後端 v0.69.0；**沒有新頁、沒有新表、沒有 migration**）

## 為什麼做這一項

學生每天評分，校方卻看不到結果。這一版把「哪道菜最不受歡迎」變成後台看得到的數字，
兩套後台（小程序內建、網頁 `/admin`）都加在同一頁，不新增頁面 —— 這一輪刻意不加新頁，
因為 49 頁裡已有一批還沒被真人看過（老師還沒改完功課）。

## 改了什麼

### 小程序後台「菜單」分頁（`pages/admin/index`）

排菜單表單下面多一段「近 30 天評分統計」（inset grouped ＋ 1rpx 髮絲線，沒有新增色值）：

- 第一列：`全校平均 4.5 · 9 道菜 · 191 則評分`（`summary` 由後端加權算好）
- 每道菜一列：菜名 ＋ `4.5 · 32 人 · 1–2 分 1`，樣本 < 3 人的右邊多一顆「樣本不足」標籤
- 最後一段：最常被評 1–2 分的菜（`番茄蛋炒飯 16.7%` 這種寫法）

**取不到統計就整段不出現**（`menuStats` 維持 `null`），排菜單照常可用 ——
不要顯示 0 讓人以為「今天沒人評分」，也不要讓一支統計把整個分頁打成「載入失敗」。

### 網頁後台「排菜單」分頁（`public/admin.html`）

多一組「評分統計」：範圍下拉（30／90／180／365 天）＋「重新整理」，一句話摘要、
五行表格（菜色／平均分／評分人數／1–2 分／按讚），下面一行寫最常被評 1–2 分的菜。
所有數字都來自同一支端點，兩套後台不會各算一套。色值沒有新增（沿用 `:root` 既有變數，
`tests/admin-ui.test.ts` 綠）。

### 示範層（`services/mock.js`）

`DISH_LIBRARY` 的評分基底從「手寫 sum／count」改成 **1–5 分分佈 `dist`**，
`seedScores()` 由分佈反推 sum／count —— 否則「平均分」與「分佈」會是兩份各自維護的真相。
新增 `seedDist()`、`data.dishDist`、`mock.menuStats()`（與後端同一組規則：加權平均、
1–2 分比例、樣本 < 3 不排名）；`rateDish()` 改分時同時更新分佈。
`SEED_VERSION` 19 → **20**（舊 storage 自動重建）。
示範資料沒有評分時間戳，`days` 在示範層只是回傳值；真 API 才是真的按天過濾。

### 使用說明

`pages/help` 校內職員分頁多一條 Q&A：「學生每天都打分數，校方看得到哪道菜最不受歡迎嗎？」
（寫出實際入口、兩套後台差別、樣本不足的規則）；`utils/i18n-phrases.js` 重建為 **1867 組**。

## 已知缺口

- **兩套後台的畫面都沒有在開發者工具裡親眼看過**（2026-11-07 老師還沒改完功課，
  使用者無法協助驗畫面）。已驗的是：後端 8 項 e2e、示範層 6 項資料層檢查、
  網頁後台 JS 語法（`new Function` 全段通過）與色值守門。
- 小程序後台這一頁的實際排版（表格列在窄屏會不會擠、`pv-tag` 與菜名同一列的寬度）
  要等有人打開才看得到；樣式用的是既有 `.ui-list--grouped`／`.signup-row`／`.chip--ghost`，
  沒有新寫 CSS，風險主要在資料長度（長菜名 + 樣本不足標籤）。
