# v0.115.0 — 通知中心分組：六個口袋、分組未讀、只清一組（2026-11-07）

任務：W-96（前端 v0.115.0／後端 v0.67.0；**沒有新頁面、沒有新表、沒有 migration**）

## 為什麼做這一項

通知匣是一條長清單：活動改期、認領結果、功課提醒、假單批准全部按時間混在一起，
開學兩週後就找不到「上星期批准的那張假單」。

更根本的問題在資料層：圖書館、假單、場地三支流程的通知**全部寫成 `SYSTEM`**，
所以就算畫面想分組，資料本身也分不出來 —— 這一版先把 `kind` 補對，再做分組。

## 做了什麼

### 後端（v0.67.0，細節見後端 repo `docs/releases/v0.67.0.md`）

- `src/lib/notify-groups.ts`（新檔）：`ALL／HOMEWORK／LIBRARY／APPROVAL／REPAIR／OTHER` 的 kind 對照，只有這一份。
- `GET /notifications?group=` 回 `group` 與 `groups`（六列 total／unread）；`unread` 仍是全部未讀數。
- `PATCH /notifications/read-all`（可帶 `group`），條件一律帶 `userId`；非法 group → 422。
- 圖書館→`LIBRARY`、假單→`LEAVE`、場地→`BOOKING`（舊資料留在 `SYSTEM`，出現在「其他」）。

### 前端

- **`pages/notifications`（既有頁，沒有新頁）**：上方加一排 chips（全部／功課／借閱／審批／報修／其他），
  每顆右邊帶那一類的未讀數（>99 顯示 `99+`、0 不顯示）；點一顆只載那一組（`data.notifications({ group })`）。
  標題列改成「這組幾則未讀 ＋ 清空本組未讀」（切在「全部」時文案是「全部標為已讀」）。
  清完**重抓整個回應**而不是只把本地 items 標已讀 —— 否則 badge 與其他組的數字會停在舊值。
  空狀態分兩種：整匣沒通知 vs「這一組沒有通知，切回全部看其他」（後者多一行指引）。
- **`services/{api,mock,data}.js`**：`notifications(opts)` 收物件也接受舊的 boolean（`true`＝只看未讀），
  `notificationsUnread(group)`、`readAllNotifications(group)` 三層同步。
- **示範層**：同一份 kind 對照，示範通知補到 9 則（含 `LIBRARY`／`LEAVE`／`BOOKING`／`REPAIR` 各一），
  已讀狀態寫進 storage（重開仍記得）。**順手修掉一個靜默 bug**：`notificationsUnread` 原本用
  `this.notifications(...)`，但 `data.js` 是 `mock[name].apply(null, …)` 呼叫 → `this` 是 null，
  示範模式的未讀數一直是 0 且沒有任何錯誤訊息；改成模組層函式。
- **設計**：chips 用 `flex-wrap`（六顆字很短，一次看得到全部；`scroll-x` 會把後面幾顆裁掉），
  未讀標記由 `box-shadow: inset` 改成 6rpx 左側色條，卡片圓角收回 `--pv-r`（20rpx）。

## 未驗到的

- **畫面未親眼驗**（老師今天仍在改功課，使用者沒法看模擬器）：chips 的換行、`99+`、
  空狀態文案與左側色條的實際觀感只由靜態守門與資料層驗證，沒有截圖也沒有人眼確認。
- 示範模式的「已讀狀態重開仍記得」只驗了 storage 寫入路徑（`check-data-layer`），沒有關掉再開模擬器實測。

## 設計取捨

- **不做 tabBar 角標**：`app.json` 沒有 tabBar（自訂導航），首頁鈴鐺本來就顯示數字。
- **卡片不再分組內再分卡**：分組只是篩選，版面維持原本一條清單，不把每一類包成一張卡（避免「每項一張卡」的模板感）。
- **舊通知不追改 kind**：把 `SYSTEM` 改寫成新 kind 等於改寫使用者已看過的紀錄，也分不出原本是哪一類。
