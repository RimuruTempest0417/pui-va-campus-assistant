# v0.128.0 — W-109 個人校曆訂閱（我的報名／假單／功課截止搬進手機日曆）

> 前端 v0.128.0｜後端 v0.77.0
> 日期：2026-11-08

## 這一版解決什麼

上一版（W-108）能匯出全校的公告與活動，但**匯出是一次性的**：下載那一刻有什麼就固定了。真正每天會瞄一眼的地方是手機內建日曆，而它會自己回來抓 —— 差的就是一條「可訂閱的網址」。

這一版把那條網址做出來，順便解決上一版做不到的事：**只有本人看得到的行程**也可以放進去（我報了哪個活動、哪張假單批了、哪份功課什麼時候截）。公開內容仍是同一支查詢，個人行程只是「加上去」。

## 做了什麼

### 後端（v0.77.0）

- `User.calendarToken`（128 bit 隨機 hex，唯一索引）＋ `calendarTokenAt`，一支 migration（第 38 支）。
- 三支管理端點（都要登入）：
  - `GET /api/v1/me/calendar/token` — 有沒有開、路徑、產生時間（未產生回 `enabled: false`）。
  - `POST /api/v1/me/calendar/token` — 產生／**重新產生**（直接換掉舊值，舊網址立刻失效）。
  - `DELETE /api/v1/me/calendar/token` — 撤銷。
- 新端點 `GET /api/v1/calendar/me.ics?token=…&days=90`（**用權杖不用 JWT**：日曆 App 訂閱時不會帶 `Authorization`）：
  - 內容＝公開的公告與活動（呼叫 `lib/calendar-export.ts`，與 `/calendar/export.ics` **同一支查詢**）＋
    我的報名（正取／候補，已取消不出）、已批准的假單、本人班別的功課截止日。
  - 報名資訊是**合併**進該活動的 `DESCRIPTION`，不是多開一個事件 —— 同一個活動在日曆上只能有一筆。
  - 個人行程的 `UID` 帶 `me-` 前綴（`me-leave-<id>`／`me-homework-<id>`），與公開那份不會撞號。
  - 權杖不符／已撤銷／帳號停用一律 **404**（同一句訊息，不揭露權杖是否存在）；`cache-control: private, max-age=300`；寫 `x-event-count`／`x-personal-count`。
  - `days` 7–365 預設 90，亂填 422（與 W-108 一致）。
- 家長（`PARENT`）：額外包含**已綁定子女**的報名與已批准假單（一律用 `parent_links` 反查，不吃任何前端傳來的 id）。
- **不寫審計**：訂閱是日曆 App 每幾小時自己打一次，寫了只會把真正該看的紀錄淹掉。
- 重構：把「哪些公告與活動算校曆內容」從 `routes/calendar.ts` 抽到 `lib/calendar-export.ts`（`exportWindow`／`fetchPublicItems`／`plainText`／`macauTime`），兩支端點共用一份口徑。W-108 的 9 項 e2e 一行沒改、全部照綠，證明重構沒有改行為。

### 前端（v0.128.0）

- 「設定」→「我的資料」**上方**多一組「訂閱校曆」：狀態一行（未開啟／已開啟）、產生網址、複製網址、重新產生（確認框寫明「舊網址會立刻失效」）、停止訂閱。
- `services/{api,mock,data}.js` 三支都補 `calendarToken`／`rotateCalendarToken`／`revokeCalendarToken`；示範模式只模擬「權杖的存在與撤銷」（存 storage，重整還在），**不會假裝生出一份可用的日曆**。
- 使用說明：學生那條「怎麼把校曆放進手機的行事曆？」改寫成自助流程（原本叫人去找老師下載檔案），家長分頁新增一條（孩子的假單與功課截止也會進去）。
- `docs/openapi.yaml` 補 4 個操作（202 路徑／246 操作）。

### 刻意沒做

- **不做「一鍵加入日曆」的深層連結**（`webcal://`）：微信內建瀏覽器開不起來，按了只會沒反應。
- **不讓權杖有期限**：日曆 App 不會處理「權杖過期請重新授權」，過期等於訂閱默默停掉。改成「無期限 ＋ 可隨時重新產生／撤銷」，安全邊界交給使用者那一顆按鈕。
- **不新增頁面**：設定頁加一組列就好。49 頁裡還有一批沒被真人看過，這輪不加新頁。

## 設計取捨

| 選擇 | 為什麼 |
|---|---|
| 權杖放 query 而不是 header | 日曆 App 訂閱時只給一條網址，沒有任何地方可以填 header |
| 權杖不是 JWT | JWT 會過期 → 訂閱默默停止；而且貼在別人的伺服器上等於長期外流 |
| 錯誤一律 404 | 只要會分辨「有沒有這個權杖」，這支端點就是探測器 |
| 報名合併進活動而不是另開事件 | 同一個活動在日曆上出現兩次，使用者會以為報了兩場 |
| 家長用 `parent_links` 反查 | 前端傳來的 id 不可信；這也是 W-102 匯出用的同一個閘門 |
| 不寫審計 | 訂閱每幾小時打一次，審計會被淹掉；要查的是「誰改了什麼」不是「誰刷新了日曆」 |
