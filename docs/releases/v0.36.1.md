# v0.36.1 — 修正 34 處相對 require 路徑（整頁空白的真凶）（2026-10-24）

## 問題

線上錯誤記錄出現 `pages/items/list/index` 的
`module 'pages/utils/i18n.js' is not defined, require args is '../../utils/i18n'`。

追下去發現不是單一頁面：v0.35.0 加 `utils/i18n.js`、v0.36.0 加 `utils/appearance.js` 時，
**20 個頁面共 34 條 require 少寫一層 `../`**。這些頁面一打開就在模組載入階段拋錯，畫面全白，
但：

- 模擬器「刷新」不會報（編譯是過的，錯在執行期）
- `check-data-layer.mjs` 全綠（它自己用 Node 載入 `services/`，不經過頁面 require）
- `check-project.mjs` 原本也不看 require 目標是否存在

也就是**三層自檢同時漏掉同一類錯**，這才是真正該修的地方。

## 做法

1. 掃全專案 55 個 `.js`，把解析不到的相對 require 依「專案根目錄下的同名模組」重新算出正確相對路徑（34 條、20 檔）
2. `check-project.mjs` 新增**第 14 項守門**：靜態解析每一條 `require('./…')`，指不到檔案就判錯，訊息直接寫「路徑層數錯了，執行期會 module is not defined」

守門用「故意改壞」驗過：把 `pages/calendar/index.js` 的 `../../utils/appearance` 改回 `../utils/appearance`，
檢查立刻回 1 個錯誤；還原後 0 錯 0 警。

## 為什麼不用人工複審就好

因為這類錯誤**完全靜默**：沒有編譯錯誤、沒有警告、`console` 一行都不會有（等到頁面被打開才炸），
而「新增一個 util」是每週都在做的事。能靜態判定的東西就不要靠眼睛。

## 驗證

```
資料層          65/65 ALL PASS

殘留壞 require  0（修正前 34）
```

## 沒驗到的

開發者工具這一輪 `loginExpired: true`（登入態過期），所以我**沒有**親眼在模擬器打開受影響頁面確認不再白屏。
路徑修正本身是靜態可判定的（`check-project` 第 14 項已擋），但「畫面真的正常」這一項要等下次登入後補驗。
