# v0.126.0 — W-107 公告已讀率（各級切片＋完整名單 CSV）

> 前端 v0.126.0｜後端 v0.75.0
> 日期：2026-11-08

## 這一版解決什麼

`notice_reads` 從 v0.20 就在寫資料，v0.54 也給了「已讀 3 / 25」與催讀。但老師真正會問的是**「是學生沒看，還是家長沒看？」**——一個總比率答不了這個問題，於是發完緊急通告仍然只能憑感覺。

這一版把庫裡已經有的資料切成決策需要的形狀：**六級各一列**、**第一次／最近一次已讀時間**、以及**完整名單 CSV**（畫面上只能列 30 位）。

## 做了什麼

### 後端（v0.75.0）

- `GET /admin/notices/:id/read-stats` 補四個欄位：
  - `byRole`：六級各一列（`PARENT`→`SUPER_ADMIN`，**即使該級 0 人也照列**），每列 `read`／`total`／`unread`／`rate`／`label`。
  - `firstReadAt`／`lastReadAt`：這一則公告第一次、最近一次被誰打開過。
  - `audience`：`total` 的別名（新呼叫端讀這個名字，舊的照樣讀 `total`，不破壞相容）。
  - `rate` 在**分母 0 時回 `null`**（原本回 `0`）。「沒有人可讀」與「0% 看過」是兩件事，前者不該顯示成 0%。
- 新端點 `GET /admin/notices/:id/read-stats/export?status=ALL|READ|UNREAD`：
  - CSV 帶 UTF-8 BOM、`x-row-count`、`content-disposition`（`notice-reads-<id>-YYYY-MM-DD.csv`）。
  - 欄位：姓名／角色／年級／班別／學號／狀態／已讀時間；學號由 `sc:` 家校通帳號抽出**純數字**（`pv` 前綴不是學號的一部分）。
  - 逐人已讀屬個資 → 寫一筆 `notice.read_export` 審計（含 `status` 與列數）。
  - 上限 5000 列；能力與 `/read-stats` 相同（`notice:create`）。
- 分母口徑仍只有一份：`bannedAt: null` 的帳號（停用帳號不該被期待看公告）。

### 前端（v0.126.0）

- 小程序後台「公告」分頁：
  - 每列直接寫「已讀 12 / 480（3%）」；分母 0 時寫「沒有人可讀」而不是 0%。
  - 點「名單」展開多兩段：「各級已讀」（只列真的有人的級別，`0 / 0` 是噪音）與「最近已讀」時間。
- 網頁後台「公告」分頁：同一欄位同步，展開後多兩顆按鈕「匯出完整名單」「只匯出未讀」（帶 token `fetch` + Blob，沿用假單／月報匯出的做法）。
- 使用說明：老師與校內職員那兩條公告 Q&A 改寫（各級已讀／最近已讀／完整名單只在網頁端）。

### 刻意沒做

- **小程序不提供逐人清單 CSV**：微信不能下載 CSV（`wx.openDocument` 不支援 csv），按了只會失敗。逐人清單只在網頁後台。
- **示範層沒有這一段**：後台（`services/admin.js`）一直都是只走真 API、示範模式沒有後台，所以這一版沒有在 `services/mock.js` 加一份「假的已讀統計」——加了反而會讓示範模式出現一份沒人驗過的假後台。

## 設計取捨

- **`rate` 的 0 與 null**：寧可讓前端多寫一個分支，也不要讓「沒人可讀」被讀成「發了沒人看」。這兩個結論會導致完全不同的處置（一個是去查名單，一個是去查發布範圍）。
- **六級全列 vs 只列有人的級別**：API 給全部六級（機器對齊、佔位穩定），畫面只顯示有人的（人的眼睛不需要 `0 / 0`）。分工寫在兩邊的註解裡，不讓「口徑」漂到前端。
- **CSV 不給小程序**：不是偷懶，是平台限制；與 v0.104 借閱 CSV、v0.123 出席率 CSV 同一條規則。

## 已知缺口

- 網頁後台那兩顆匯出按鈕**沒有親眼點過**（自動化只驗到端點與語法）。
- 小程序「各級已讀」的排版沒有真機看過（資料層與頁面啟動檢查綠，但觀感未驗）。
- 這一版沒有改任何 schema、沒有 migration。
