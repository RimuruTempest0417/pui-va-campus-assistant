# v0.46.0 — 錯誤日誌整理：清理舊紀錄＋同類一次解決（W-36）

錯誤只會往上累積。到了十月中，後台「錯誤」分頁已經是一長串相似的重複項目，
真正該修的反而被淹掉 —— 這版把「整理」這件事做進後台，而不是叫你定期去資料庫手動刪。

## 做了什麼

後端（`pui-va-campus-server` v0.21.0）：

- `POST /api/v1/admin/error-logs/cleanup`：收 `{ olderThanDays: 1..365, includeOpen?: false }`，
  刪掉最後出現時間早於 cutoff 的紀錄，寫一筆審計（`error.cleanup`，帶天數／刪幾筆／保留幾筆）。
- `POST /api/v1/admin/error-logs/resolve-similar`：收 `{ message, route? }`，把同一句話的錯誤整批標成 RESOLVED；
  **省略 `route`＝不分頁面全部解決**，帶 `route` 只解決那一頁。
- `GET /api/v1/admin/errors` 的每一列多一個 `similar`（訊息相同的紀錄數），後台才有辦法顯示「同類 N 筆」。
- 兩支都走既有的 `error:read` 能力（`ADMIN` 以上），學生／老師 403、未登入 401。

前端（小程序，`pages/admin/index`）：

- 錯誤分頁摘要卡多一顆「清理舊紀錄」→ 動作表選 30／90／180 天 → 二次確認 → 提示「已清理 N 筆（保留 M 筆未解決）」。
- 每一列若有同類錯誤，顯示「同類 N 筆」標籤，並多一顆「同類一次解決」（僅 OPEN 的列出現）。
- 網頁後台（`GET /admin`）「錯誤」分頁同步同一套：`同類 N 筆` 標籤、`同類 N 筆一次解決` 按鈕、`清理舊紀錄` 下拉＋按鈕。
  兩套介面功能對齊是硬規則 —— 只補小程序會被抓成 bug。

## 設計取捨

- **清理預設只刪「已解決」的**。`OPEN` 是待辦事項，自動刪掉等於把 bug 藏起來；要連未解決一起清必須明確帶
  `includeOpen: true`（前端沒有開這個開關，只留給腳本／維運）。API 回 `kept` 讓後台老實說「還有 N 筆沒動」。
- **「同類」的定義是「同一句話」，不是「同一句話＋同一頁」。** 指紋（`sha256(message|route)`）含頁面，
  所以一支 `request:fail timeout` 出現在三個頁面就會是三列；使用者要解的其實是「這句話」，
  所以 `resolve-similar` 省略 `route` 時跨頁面一起解決。要只處理某一頁仍然可以帶 `route`。
- **已 RESOLVED 的不重算 `resolvedAt`**：回 `{ matched, resolved }` 兩個數字，`resolved` 才是這次真正翻動的筆數，
  避免把「誰在什麼時候標的」洗掉。
- 天數上限 365、下限 1 —— 這支會真的刪資料，不提供「全清」（要全清走資料庫備份流程）。
