# v0.87.1 — 網頁後台補「圖書館」分頁（與小程序後台對齊）（2026-11-06）

> 後端 **v0.46.1**（`pui-va-campus-server`）：只改 `public/admin.html`，沒有新端點、沒有 migration
> 任務：W-70（P1。v0.86.0 的遺留缺口）

## 為什麼

v0.86.0 只做了小程序內建後台，網頁 `/admin` 沒有圖書館分頁。兩套介面的功能必須同步 ——
Gary 的驗收方式就是在網頁後台點一輪，「小程序有、網頁沒有」會被當成沒做完。
而且館藏一次要打十幾本書名、ISBN、索書號，在電腦上打字比手機快得多。

## 改了什麼

| 位置 | 內容 |
|---|---|
| `public/admin.html` | 新增「圖書館」分頁（第 14 個）：館藏與借閱紀錄兩個子模式 |
| 館藏 | 新增／修改（帶 `version`，兩人先後存會回 409 而不是靜默覆蓋）／下架與上架／刪除（有借出中不能刪）；清單顯示 ISBN、索書號、可借／總量、在架狀態、借閱次數 |
| 借閱紀錄 | 範圍切換（借閱中／逾期／已歸還／全部）、可搜書名或借閱人、逾期天數與「快到期」標記、**代還**、**一鍵催還**（只催到期前兩天與已逾期、同一筆一天一次） |
| 權限 | 沿用 `library:manage`（校內職員以上），分頁照 `enter()` 的 allowed 表隱藏；沒有新端點，直接打既有的 `/admin/library/*` |

## 設計取捨

- **不另開端點**：`/admin/library/books`、`/loans`、`/remind` 已經存在，網頁只是第二個殼。多開一支等於兩份真相。
- **刪除用原生 `confirm`、代還也用 `confirm`**：誤刪一本書要重建 ISBN 與索書號，代還則是會改變學生的借閱狀態，兩個都值得多問一句。
- **`hasMore` 直接寫在畫面上**（「只列出前 N 筆，請用搜尋縮小範圍」）：館藏超過 100 本時不假裝全部都在。

## 怎麼驗

- 前端守門全綠（`check-docs` 版本三方一致）
