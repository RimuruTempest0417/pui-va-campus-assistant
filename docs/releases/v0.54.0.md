# v0.54.0 — 示範資料層的重複方法清理（W-44）＋新守門

日期：2026-10-25

## 為什麼

`services/mock.js`（示範模式的資料層）裡有五個方法各寫了**兩份**：
`switchDemoUser`／`weekMenu`／`getDish`／`rateDish`／`topDishes`。

JS 物件字面值裡後面那份會**靜默蓋掉**前面那份。目前兩份內容逐字相同，所以畫面上完全看不出問題 ——
但只要有人只改上面那份（例如替菜單加過期過濾、替排行改排序），行為會悄悄退回舊版，
而 console、編譯、`check-project`、`check-data-layer` 全部不會有任何意見。

這是「靜默降級」的另一種形狀：不是它壞了，而是你以為改了、其實沒生效。

## 改動

| 檔案 | 改什麼 |
|---|---|
| `services/mock.js` | 五個重複方法只留一份。**逐段比對兩份內容（`diff` 結果為空、逐字相同）後**才刪，且保留位置較合理的那一份（在原處「我的報名 → 切換身分 → 菜單 → 智能匹配」的順序），刪掉後來附加在檔尾的那一份。檔頭到尾沒有其他改動 |
| `scripts/check-project.mjs` | 新增**第 19 條**守門：`services/*.js` 的 `module.exports` 第一層 key 不得重複。第 17 條只掃 `key: value` 形式的 `data`／`labels()`，抓不到方法簡寫 `foo() {}`，所以這條另外寫了一個走訪器，`a: 1`、`a() {}`、`async a() {}` 三種寫法都算 |

## 抓到的坑

- **第一版守門誤報 40 條**，全部來自 `services/data.js` 的轉接方法：
  `login: (...a) => call('login', a)` 這種「值是箭頭函式」的成員，走訪器把函式體裡的 `call(` 當成了新的 key。
  修法是加一個 `expecting` 旗標：只有在「成員開頭」（`{` 之後或 depth 1 的 `,` 之後）出現的識別字才算 key，
  一旦遇到 `:`／`(`／`=` 就不再認 —— 誤報從 40 條降到 0。
  這件事本身值得記：**守門的誤報比漏報更危險**，因為它會訓練人「看到紅燈就先忽略」。
- 原本想用一條 shell 指令盤點：`grep -n "^  [a-zA-Z]*(.*) {"`。它在 BRE 下把 `(.*)` 當成**字面括號**，
  所以五個重複方法一個都沒抓到、回報「沒有重複」—— 差一點就當成這項已經不用做。
  改用 `grep -n "\bname("` 逐個方法數次數才看到真相。**盤點指令也要先驗它抓得到已知的那一筆。**

## 設計取捨

- **保留哪一份不影響行為**（兩份逐字相同），所以選擇依據是「可讀性」：留在原本的模組分區裡，
  而不是留在檔尾臨時附加的位置。若兩份內容有差異，正確做法是**先人工合併成一份正確的**再刪，不是挑一份留。
- **守門寫在 `check-project.mjs` 而不是 `check-data-layer.mjs`**：這是「檔案結構／語法層」的病
  （同一個物件重複 key），不是資料行為的病；而且第 17 條同類守門已經在這裡，兩條擺在一起才好維護。
- **沒有改成「物件凍結」或「改用 Map」**：那些會動到整個資料層的形狀，而這輪要的只是讓「第二份」不可能存在。
