# v0.88.0 — 二手書／校服轉贈：把「用不到」變成「別人正好要」（2026-11-06）

> 後端 **v0.47.0**（`pui-va-campus-server`）：`GiveawayItem`／`GiveawayRequest` 兩張表（第 29 支 migration）＋ 9 支端點
> 任務：W-68（P1）

## 為什麼

校內每年有兩種東西一直在浪費：**換季後穿不下的校服**，與**只用一個學期的教科書**。
它們現在靠班群貼文流動 —— 三天就被洗掉，而且誰先看到誰先要，物主常常同時被五個人問。

這個模組要回答三件失物招領答不了的事：
① 東西是**送的**，不是掉的（所以不能混進失物的狀態機）；
② **物主決定給誰**（不是先搶先贏，也不是管理員審批）；
③ 贈出後前台就看不到，但參與過的人仍看得到結果（不能忽然變 404）。

## 設計取捨

- **不做軟刪除，用 `CLOSED` 表達「拿掉了」**：學生心裡的「刪除」就是「不要再出現在清單」，而 `CLOSED` 可以一鍵重新上架；硬刪要處理 FK，軟刪則要再開一個回收桶分頁（回收桶目前只收公告／失物／活動）。這一條寫進程式註解，避免下一輪有人「補一個 delete」。
- **一個補充欄位而不是兩個**：書籍填年級／科目、校服填尺碼，都只是一行說明。開兩個欄位會讓表單變長、查詢也不會用到。
- **`detail`／`pickupPlace`／聯絡方式全部選填**：門檻愈低，東西愈流動得起來。真正必填的只有種類、標題與新舊。
- **不送 `wx.chooseMedia` 的本機路徑**：COS 未開通，圖片只收 http(s) 連結（與活動附件同一條規矩），不假裝上傳成功。
- **家長也可以送出與申請**（`giveaway:create`／`request` 加入 PARENT）：換季校服最常見的送出者其實是家長。這是政策變更，`tests/permissions.test.ts` 的舊斷言「家長唯一的寫入是代子女報名」已同步改掉並加註原因。
- **不做 emoji**：種類徽章用單字（書／服／物），入口用新畫的禮物盒線性圖標（`pv-icon name="gift"`）。
