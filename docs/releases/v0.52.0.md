# v0.52.0 — 使用者手動回報問題（W-43）：設定頁一句話就送到管理員

日期：2026-10-25

## 為什麼

到目前為止，前端只有 `app.onError`／未處理 Promise 會自動上報。
「按鈕按下去沒反應」「畫面怪但沒有錯誤」這類問題**不會拋錯**，學生只能口頭跟老師講，
老師再轉述給管理員 —— 傳到最後只剩下「有人說壞了」，哪一頁、什麼手機都不知道。

## 抓到的坑

- **示範模式的「成功」也是假成功**：第一版 `mock.reportIssue` 直接回 `{ok:true}`，
  於是畫面彈「已送出，謝謝你的回報」而其實什麼都沒送出去 —— 正是 Gary 最在意的靜默降級。
  改成回 `demo: true`、畫面照實說「示範模式沒有送出」。
- **空白訊息**：`String('   ')` 是真值，`!text` 的檢查擋不到；要 `trim()` 後再看長度
  （`check-data-layer` 的「空訊息被拒」就是為了這條而寫的）。

## 設計取捨

- **回報走既有的 `client-errors` 家族**，不新開一組端點：節流、聚合、後台分頁全部共用。
- **同一張 `error_logs` 表用 `kind` 分兩種來源**：修的人只要記一個「錯誤」分頁；
  但指紋分開（`report|` 前綴），所以「使用者說有問題」不會跟同一頁真的拋的錯混成一列。
- **入口放設定頁、不放在首頁**：首頁的規則仍是「首屏可點元素 ≤ 6」，
  而回報是低頻操作；設定頁本來就是「找不到東西時會去翻」的地方。
- **不在小程序做「回報紀錄」清單**：使用者送完就是送完了，追蹤是管理員的事；
  多一個清單只會讓人期待「有回覆」，那需要另一整套流程（後續 W 編號再談）。
