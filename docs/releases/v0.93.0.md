# v0.93.0 — 搜尋加類型篩選：五類結果可以只看一種（2026-11-06）

> 前端 v0.93.0；後端無改動（仍 v0.50.0，`/search` 的 `types` 早就支援）
> 任務：W-75（P2）

## 為什麼

菜單接進來之後（v0.92.0），一次搜尋可能同時出現公告、活動、失物、轉贈與菜單五組。
找「我要的是那件失物」時得多掃好幾眼；`/search` 本身早就有 `types` 參數，只是頁面沒有 UI。
這一版把它接出來：搜尋框下方一排 chip（全部／公告／活動／失物／轉贈／菜單）。

## 改了什麼

| 位置 | 內容 |
|---|---|
| `pages/search/index.js` | 新增 `typeFilter`（預設 `all`）＋ `filters()`（六顆 chip，語言切換時重建）＋ `pickType()`：切換就**重跑一次查詢**（`data.search(word, { types })`），不是在前端過濾已抓回來的結果 —— 每一類的「看得到」規則在後端，前端過濾等於抄第二份；而且原本就被 `limit` 截斷，前端過濾只會讓「只看失物」比實際少。`all` 不帶 `types`（五類一起回） |

| 守門 | `check-data-layer` +2（頁面真的把 `types` 帶進請求／請求層吃兩種形狀）→ **174/174** |

## 設計取捨

- **切 chip 重打一次 API，不在前端 filter**：`limit` 是「每一類最多幾筆」，前端過濾後「只看失物」會少於實際；可見性規則也只有後端那一份。
- **chip 有輸入才顯示**：首屏是「想找什麼？」的提示與最近搜尋，多一排 chip 會讓人先選類別再想關鍵字（順序反了）。
- **不加「最近搜尋 + chip」的組合記憶**：一個關鍵字可能在五類裡找過，記類別只會讓下次點歷史時結果變少。
- **chip 用 pill、不用分段控制**：六顆在窄屏會換行，分段控制在換行後看起來會斷掉。

## 沒做的（刻意）

- **不做「搜尋結果計數」在 chip 上**（例如「失物 2」）：要算就得對五類各打一次，成本換不到多少。
- **不把 chip 狀態寫進 storage**：每次進來都從「全部」開始，避免上次的限制延續到這次。
- **UI 觀感未親眼驗**：這一輪沒開開發者工具；chip 的換行與按壓手感請以真機／模擬器為準。
