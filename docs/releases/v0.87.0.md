## 為什麼

實驗室、球場、投影機到現在還是「在群組裡問一句有沒有人用」：同一個時段兩個人各問一次，兩個都以為自己借到了。
圖書館解決的是「一本書同時只能借給一個人」，場地借用解決的是**「一段時間同時只能有一組人用」** ——
是同一類併發問題的另外一個形狀，所以沿用「交易內列鎖」的做法，而不是另外發明一套。

## 抓到的 bug（自己踩的）

- **示範層 id 撞號**：`'rb' + Date.now()` 在同一毫秒連續建立兩筆時會重複，症狀是「批了第一筆之後，第二筆說已經處理過了」。改成模組層遞增序號 `nextId()`。
- **`dateOptions(2)[2]` 越界**：只給 2 天的選項卻取第 3 個，種子資料在載入時直接 `Cannot read properties of undefined`。改為 `dateOptions(3)`。
- **WXML 的 `range="{{[L.a, L.b]}}"`**：陣列字面值在模板裡不可靠，改成 data 的 `venKindLabels`。
- **YAML 未加引號的 `例 10:00–12:00`**：第二個冒號讓整份 openapi.yaml 解析失敗（write_file 直接拒寫，這次是好事）。

## 設計取捨

- **PENDING 也佔用時段**：只有 APPROVED 才算的話，兩個人可以同時進待審，老師批了兩筆才發現撞期。代價是「送錯要自己取消」——所以詳情頁把我的申請放在最上面。
- **半開區間 `[start, end)`**：A 借到 10:00、B 從 10:00 開始不算重疊。校內最常見的用法就是「接著上一班」，用閉區間會逼大家自動留 30 分鐘緩衝。
- **不支援跨夜借用**：實驗室與球場都不開過夜，允許跨日只會讓「同一天」的判斷變複雜（而且時段檢查要用兩個日期）。
- **老師只負責審批、職員負責登記**：`resource:approve` 給 TEACHER 與 STAFF、`resource:manage` 只給 STAFF 以上 —— 老師不需要為了批一場球賽去學怎麼建實驗室。
- **同時段還有另一筆待審時，批准會失敗**：不自動駁回另一筆，因為「批哪一筆」是人的決定，系統不該替他選。
