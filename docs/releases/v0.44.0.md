# v0.44.0 — 列印版頁面（W-28 尾巴，A4 黑白）

## 為什麼做這個

老師的需求很具體：「失物清單要貼佈告欄、活動當天要點名，學校有印表機但沒有電腦在旁邊。」
後台網頁版（v0.41.0）雖然有 `@media print`，但那是「坐在電腦前」的路徑；手機上沒有出口。
所以補兩個小程序內的 A4 黑白頁面，入口就在後台分頁上。

## 怎麼運作

| 入口 | 頁面 | 內容 |
|---|---|---|
| 後台 → 失物 → 「列印清單」 | `pages/print/items` | 目前篩選狀態的失物清單（狀態 chips 可在頁內切換，預設「待認領」），最多 200 筆（連續抓 4 頁 × 50） |
| 後台 → 活動 → 該場「列印名單」 | `pages/print/event` | 該場活動的正取／候補名單：序號、姓名、年級、班別、狀態、報名時間 |

版面（`styles/print.wxss` 共用）：

- **白底黑字、細灰線、無圓角無陰影**：影印後不會出現灰塊；列印頁強制 `.theme-light`，深色模式下手機也是白紙。
- **紙高不是寫死的 px**：用 `wx.createSelectorQuery` 量可用寬度 × A4 比例（297/210）算出紙高，
  再扣掉表頭／表尾、除以量到的列高得到「每頁幾列」（夾在 8–40 之間）。量不到就回預設 22 列——
  回 0 會讓畫面整片空白且 console 不報錯。
- **每頁列數固定**：同一份清單每張紙列數一致，不會第一頁特別長、後面斷在奇怪位置。
- **「列印預覽」**：一鍵把工具列與按鈕收起來，只看得到紙。
- **「複製表格」**：小程序沒有列印 API，所以把表格複製成 Tab 分隔文字（`utils/print.js` 的 `toTsv()`，
  會清掉欄位內的 tab／換行），貼進 Word／Excel 就是一張表，這是手機端真實可走的列印路徑。

## 資料從哪來

- 失物清單：`services/data.js` 的 `listItems()`——與失物列表同一支入口，示範模式也看得到。
- 活動名單：`services/admin.js` 的 `signups()`（後端 `GET /admin/events/:id/signups`，能力 `event:export`）。
  所以這一頁會遇到三種非 happy path，各自給出口而不是一句「載入失敗」：
  未登入 → 「請先登入教職員帳號」＋去登入；403 → 「這個帳號沒有匯出報名名單的能力」；
  示範模式 → 明說「示範模式沒有後台名單，請用真 API 模式」（示範模式沒有後台，不做假名單）。

## 順手修掉的守門漂移

`check-states.mjs` 一跑就抓到 **2 頁從沒登記**（`pages/help`、`pages/notifications`），代表三態守門一直沒涵蓋它們：

- `pages/help`：純站內說明，登記成 N/A 並寫明原因。
- `pages/notifications`：**真的缺失敗態** —— 讀取失敗時清單是空的、畫面顯示「還沒有通知」，
  等於把「讀不到」講成「沒有」。已補 `failed`／`errorText`＋重試，失敗時顯示「讀不到通知」與錯誤碼。

模擬器實測（實跑，不是推論）：

| 檢查 | 結果 |
|---|---|
| 失物清單（示範資料 5 筆） | 紙 403×569、**比例 1.414（A4）**、每頁 17 列、5 筆 1 頁；「列印預覽」可切換收起工具列 |
| 活動名單（真 API `GET /admin/events/:id/signups`） | 標題讀到「通知測試活動」、meta 顯示時間／名額、名單 0 筆走空狀態；console 無 error／warn |
| 活動名單（注入 30 筆假資料驗版面） | 每頁 16 列（表頭三行較高）、30 筆切 2 頁 16／14、姓名欄 111px 未被壓扁 |
| 示範模式打開時的活動名單 | 走「示範模式沒有後台名單」狀態（不造假名單） |
| 真實空清單（線上目前 0 筆失物） | 走空狀態，不顯示空紙 |

**實測抓到並修掉的兩個 bug（靜態守門抓不到，只有量 rect 才會現形）**：

1. `setData` 回呼比排版快，第一次 `createSelectorQuery` 拿到 null → 紙高一直是 0（紙不受高度約束、列數停在預設），
   而且 early-return 讓它永遠不再重試。修法：`scheduleMeasure()` 沒量到紙高就 200ms 後重量一次；
   量不到寬度時直接 return，不要拿預設值覆蓋已算好的結果。
2. 用容器（`.print-inner`）寬度算紙高，但容器含內距 → 紙的實際比例是 1.509（比 A4 高約 7%）。
   修法：改成量 `.sheet` 自己的寬度，實測回到 1.414。

## 設計取捨

- **不做 canvas 產圖／存相簿**：那條路要處理字型、分頁、縮放，出錯時使用者拿到的是模糊圖；
  複製表格（TSV）零失敗率，貼進 Word 排版反而更像正式名單。
- **活動名單沒有「組別」欄**：`GET /admin/events/:id/signups` 目前不回 `groupKey`（CSV 才有）。
  為了不為了一個欄位動後端與線上部署，本版先不顯示；若之後要印分組名單，再加欄位與 migration。
