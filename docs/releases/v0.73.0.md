# v0.73.0 — 催填回饋（W-56）

後端對應版本 **v0.34.0**。

## 做什麼

W-55 讓老師看得到回覆率，但看到的往往是很低的值（3 ÷ 25 ＝ 12%）。
在那之前老師只能口頭催，因為**系統裡沒有任何地方可以按**。這一版補上那個按鈕：

- 小程序後台「活動」→ 統計卡的**回饋區塊**多一顆「**提醒填回饋**」；
  按完就地顯示「已提醒 12 人（跳過 3 人最近催過）」，卡片不關、不重開。
- 網頁後台 `/admin` →「報名名單」分頁的「活動回饋」區塊，同一顆按鈕、同一套提示
  （Gary 的驗收方式就是在網頁點一輪）。
- 按一次＝**站內通知一定有**（點進去直接跳該活動詳情頁），
  微信訂閱消息**只在對方按過允許時**加發 —— 沒有同意記錄就不發，不騷擾。
- 回覆率已達 100%，或這場活動根本沒有人簽到時，按鈕是 **disabled**（按了也沒有人可以催）。

## 四條規則（都是刻意的）

1. **只催「正取＋已簽到＋還沒填」的人**。沒來的人不該被要求評分 —— 他沒有體驗過這場活動；
   這也讓催填的分母與 W-55 的回覆率分母（`attended`）保持一致，兩個數字不會互相打架。
2. **已填回饋的人不催**。已讀還被催一次，是使用者最直接感受到的騷擾。
3. **活動還沒結束回 422**。回饋是在活動結束後才開放（`POST /events/:id/feedback` 同一條規則），
   提前催只會讓學生點進去看到「活動還沒結束」。
4. **同一活動 12 小時內催過的帳號跳過**（靠 `PushLog` 查，不新增資料表）——
   老師連點兩下、或兩個老師同時按，都不會發兩輪。

## 設計取捨

- **不新增資料表**：去重直接用既有的 `PushLog`（`channel: INAPP`、`scene: EVENT`、標題＝`回饋提醒：<活動名>`）。
  為了讓查詢認得出「同一場活動的同一輪催填」，標題格式必須固定 —— 改文案就等於讓去重失效。
- **重抓回饋統計**：按完會再抓一次 `feedback-stats`，因為催的同時可能剛好有人填了；
  不重抓的話老師會看到「催了但回覆率沒動」，很像按鈕沒生效。
- **按鈕放回饋區塊內，不放到 `row-actions`**：`row-actions` 那一列是活動層級的操作（候補轉正／關閉），
  催填只跟回饋有關，放進去會讓人以為它動的是整場活動。

## 已知缺口

- 小程序端的按鈕外觀（disabled 時的對比、按完提示換行）只驗到資料與結構，
  **沒有親眼看到觀感**；手感與版面仍需看一次模擬器或真機。
- 微信訂閱消息這條路徑在示範環境沒有模板 id（`WX_TPL_EVENT` 留空 → 直接跳過），
  所以「有同意的人真的收到微信」只驗到程式分支，沒有實際送達紀錄。
