# v0.24.0 — 活動現場簽到（QR）：老師出碼、學生掃碼、出席率（2026-10-24）

## 做什麼

- **老師端（小程序內後台「活動」分頁）**：每張活動卡多一顆「簽到」→ 原地展開簽到面板：
  大 QR（`image` 直接吃 `data:image/png;base64,…`）＋ 6 位數字碼 ＋「已簽到 n / 正取 m（出席率）」，
  可按「開始簽到」（每次換新碼，舊碼立刻失效）／「結束簽到」／對個別學生「代簽」「撤銷」。
- **網頁後台（`GET /admin` → 報名名單）**：同一套簽到面板（產生／更換碼、結束簽到、即時出席數）。
  兩個殼共用同一支後端路由，功能對齊。
- **學生端**：新頁面 `pages/events/checkin`（掃碼／手打 6 位碼），入口在「活動詳情」與「我的報名」——
  只有正取看得到，已簽到就顯示「已簽到」不再給按鈕。
- **後端**：`events.checkInCode/checkInActive/checkInOpenedAt`＋`event_signups.checkedInAt/checkedInBy`；
  新能力 `event:checkin`（老師以上）；6 支端點：
  `GET /events/:id/checkin`、`POST /events/:id/checkin/{open,close}`、`GET /events/:id/attendance`、
  `POST /events/checkin`（學生自簽）、批次 `CHECK_IN`／`CHECK_OUT`；`/events/:id/stats` 多 `checkedIn` 與 `attendanceRate`。
- **QR 由後端產生**（`qrcode` → PNG data URL），內容 `PVCHECKIN:<6 位碼>`；學生端接受 QR 內容、
  帶 `code=` 的網址、或純數字三種輸入，解析寫在 `lib/checkin.ts` 的 `parseScanned()`。

## 抓到的 bug

- **真 API 模式下活動詳情不顯示「我已報名」**：`utils/event.js` 的 `decorate()` 只認示範資料的 `mySignup`，
  真 API 回的是 `myStatus` → 一律被覆寫成空字串，學生明明報了名，詳情頁還是顯示「立即報名」。
  改成兩種來源都認（`myStatusOf()`），並在資料層自檢加一條釘住。

## 設計取捨

- **不另開 `checkin_sessions` 表**：一次只會開一個簽到時段，多一張表只是為了保存歷史時段，
  代價（多一次 join、多一組清理邏輯）大於收益。要換碼就重開一次。
- **只認碼、不認前端傳來的 eventId**：否則改一個參數就能替別人簽到。
- **候補不算出席**：代簽只動 `status = CONFIRMED`，所以候補那筆在批次操作裡 `affected` 不計；
  重複掃回 `already: true` 而不是錯誤，免得學生在門口看到紅字。
- **出席率沒有人報名時回 `null`**，不顯示 0%（那是錯的資訊）。
- **QR 在後端產生**：小程序端不必塞一份 QR 編碼器進代碼包（也沒有可靠的 Skyline 相容性），
  同時讓出席統計與碼的產生在同一個服務裡，避免「前端算一套、後端算一套」。
