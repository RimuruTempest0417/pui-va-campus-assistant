# v0.48.0 — 後台統計首頁（W-39）

- 日期：2026-10-25
- 前端 `0.48.0`｜後端 `0.23.0`
- 範圍：W-39 後台統計首頁（兩套後台同步）

## 做了什麼

### 後端：`GET /api/v1/admin/stats/overview`（能力 `stats:read`）

一次回五個即時 count，全部即時查、不快取：

| 欄位 | 意思 | 定義 |
|---|---|---|
| `usersNew7d` | 本週新使用者 | `User.createdAt ≥ 7 天前` |
| `signups7d` | 本週報名 | `EventSignup.createdAt ≥ 7 天前` 且狀態 `CONFIRMED`／`WAITLIST` |
| `claimsPending` | 待審認領 | `ItemClaim.status = PENDING` |
| `errorsOpen` | 未解決錯誤 | `ErrorLog.status = OPEN` |
| `itemsOpen` | 未認領失物 | `LostItem.status = OPEN` 且未下架（`deletedAt = null`） |

- 另回 `week: { from, to }`，讓前端不必自己算窗口。
- 「本週」＝**滾動近 7 天**，不是週一到週日：避免時區與週界爭議，也和既有的 `items.added7d` 一致。
- 為什麼另開一支而不是塞進 `GET /admin/stats`：那支是**累計報表**（總使用者／總活動／評分平均），
  這支是**本週五個數字**、會被畫成第一屏可點的卡片，語意與更新頻率都不同。兩支都掛 `stats:read`。

### 前端（小程序）`pages/admin/index` 概況分頁

- 第一屏新增「本週概況」五張數字卡：本週新使用者／本週報名／待審認領／未解決錯誤／未認領失物。
- **點卡片跳到對應分頁**（使用者／名單／認領／錯誤／失物），不用自己找。
- 卡的標籤與跳轉目標由 `buildOvCards()` 一起備好（WXML 不做運算），要改「點卡片去哪」只改一處。
- 下方原本的六格數字加上「累計」小標，語意分清：上面是「這週＋待辦」、下面是「累計」。
- `statsOverview()` 失敗時**不影響累計數字**（`Promise.all` 的第二支自帶 `catch`）：
  加值資訊掛掉不該讓整頁變成「讀取失敗」。

### 前端（網頁）`public/admin.html` 營運數據分頁

- 同一支端點、同樣五張卡排在最上面，可點跳分頁；沒有該分頁權限的帳號不顯示那張卡（讀 `state.allowed`，沿用既有分頁權限表）。
- 卡片讀不到時顯示「本週數字暫時讀不到；下方累計數字不受影響」，不讓整頁空白。

## 抓到的坑

- **openapi 插入新 path 時不要把下一個 path 的 key 一起吃掉**：這次用 `patch` 把
  `'403'` 那行當錨點、新區塊寫在後面，結果 `/dishes/{id}:` 這一行被取代掉，
  變成「新 path 底下接著別人的 `parameters`」——`check-openapi` 仍能解析（因為 YAML 還合法），
  但 `/dishes/{id}` 從此消失。**判斷方式**：插入後立刻數 `paths` 的數量（92，不是 91），
  並確認被插入位置前後兩個 path 都還在。修法是把被吃掉的 key 補回。

## 設計取捨

- **不做快取**：後台同時在線的人個位數，count 五支都在 10ms 內；快取只會製造
  「我明明審完了，卡片還是舊的」這種最傷信任的症狀。
- **報名數不含已取消**：已取消的列留在資料庫是為了審計與候補順序，
  但算進「本週報名」會讓卡片數字比名單多，看起來像對不上。
- **未認領失物不含已下架**：卡片要回答「學生還看得到幾件沒人要」，
  含軟刪除的話數字永遠降不下來。
