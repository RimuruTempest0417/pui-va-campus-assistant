# v0.4.1 — 修復 WXSS 編譯失敗與自檢頁錯誤（2026-10-22）

使用者回報兩個問題，追下去是同一個根因家族：**WXSS 在建置階段失敗，但模擬器刷新不會報錯**。

## 修了什麼

| 問題 | 根因 | 修法 |
|---|---|---|
| 真機調試上傳失敗：`path '../../styles/tokens.wxss' not found from './pages/dev/api-check/index.wxss'` | `pages/dev/api-check` 是三層深度，`../../` 只到 `pages/`，少了最後一層 | 改成 `../../../styles/tokens.wxss` |
| 同上錯誤訊息裡附帶 `unexpected token '*'`（三個檔案都中） | `styles/tokens.wxss` 的 `@media (prefers-reduced-motion) { * { ... } }` —— **WXSS 不支援萬用選擇器 `*`**，會讓引用它的每個 wxss 一起失敗 | 移除該規則；減少動態改列為 P2，改用逐組件具體 class 實作 |
| API 自檢頁按「重新檢查」出現錯誤 | 其實是上面兩個讓該頁 wxss 編譯失敗，頁面樣式與腳本一起掛 | 隨上面修好；並用 `rerun()` / `resetDemo()` 直接呼叫驗證，兩者都回 ok、9/9 通過、示範資料回到 4 筆 |

## 新增守門（避免再犯）

`scripts/check-project.mjs` 現在會檢查：

1. 每個 `.wxss` 的 `@import` 目標**必須存在**（按層數解析，不是靠肉眼數 `../`）
2. 不得使用萬用選擇器 `*`（WXSS 編譯器會整檔失敗）

**兩者都做過反向測試**：故意造出「三層深度的兩層路徑」與「`* { }`」兩種錯誤，腳本分別回 `exit=1` 並指出檔案；清掉後回到 0 錯誤。

## 教訓（已寫進專案技能）

- **模擬器刷新成功 ≠ WXSS 通過**：`@import` 找不到、`*` 選擇器這類錯誤只在「真機調試／上傳」跑完整編譯時才暴露 → 每次改樣式後要跑 `node scripts/check-project.mjs`，交付前用真機調試驗一次
- 相對路徑一律用腳本驗，不靠數 `../`
