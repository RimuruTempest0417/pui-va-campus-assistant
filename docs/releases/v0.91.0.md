# v0.91.0 — 請假申請：紙本假單變成有紀錄的流程（2026-11-06）

> 前端 v0.91.0／後端 v0.49.0；新表 `leave_requests`（1 支 migration，第 30 支）
> 任務：W-72（P1）

## 為什麼

請假是全校每個月都在發生的事，但整個流程在系統外：學生寫紙條託同學交給班主任、家長另外打電話、
校務處月底要統計還得回頭翻紙本。這一版把它變成「送出 → 審批 → 通知 → 可回看」：

- 學生自己在小程序送出，不必等紙本
- 家長用家校通帳號就能代子女請假（沿用既有的 `parent_links` 綁定，不需要再綁一次）
- 班主任／校務處在小程序後台或網頁後台一手批／駁
- 批完家長與學生都收到站內通知，月底統計不用再翻紙

同時補上一個原本沒人管的情境：**同一段日期不能有兩張算數的假單**（待審批或已批准），
否則老師批完兩張、月底統計就會把請假日多算一次。

## 設計取捨

- **日期只到「天」**：請假是「哪幾天不在」，不是幾點到幾點。`@db.Date` ＋ 純字串 `2026-11-12` 兩邊一致，前端 `picker mode="date"` 直接回這個格式，不必再做時區換算。
- **取消是改狀態，不是刪列**：已批准的假單被刪掉，月底統計就會少一天。所以只有 `PENDING` 能取消，其他狀態回 409 並說明要找老師。
- **審批用條件式 UPDATE**：`updateMany({ where: { id, status: 'PENDING' } })`，`count === 0` 回 409 —— 兩位老師同時按批准時只有一位成功。用「先讀再比再寫」在併發下會兩個都成功，這正是要擋的事。
- **家長只建「帳號裡那一位」的流程**：家校通一個家長帳號對應一個孩子，所以 UI 不做子女 chips，直接顯示名字；後端仍走 `parent_links` 反查（不信前端傳來的 `studentId`），越權與不存在回同一句 403（防學號探測）。
- **通知發給「送出者」與「學生本人」兩個 id（去重）**：家長代請假時是兩個不同的人，只發其中一個都會有人說「我沒收到」。
- **升級路徑不動**：學生與家長的假單都落在 `studentId`，老師看的是「誰不在」，不是「誰按的送出」；`createdById` 只用在後台顯示「家長代送」與審計。

## 沒做的（刻意）

- **不改已批准的假單**（改期要找老師取消再重送）：改期要留「原本批了哪幾天」的紀錄，這一版沒有審批歷史表。
- **不做附件上傳**：`attachmentUrl` 欄位留著（病假紙／醫生證明），但 COS 未開通前上傳會假成功，所以表單先不收。
- **不做「全校請假月報」**：校務處要統計目前得自己篩日期；等有實際需求再加一支彙總端點，不在這一版先猜格式。
- **手勢與觀感未親眼驗**：這一輪沒開開發者工具（自動化會打斷使用者手動操作），按壓手感與版面請以真機／模擬器為準。
