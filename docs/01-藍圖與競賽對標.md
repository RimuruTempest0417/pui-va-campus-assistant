# 培華校園助手 Pui Va Campus Assistant — 藍圖與競賽對標 v1

> 定位：澳門培華中學師生專用的校園服務小程序
> 用途：學校考試作品 ＋ 報名參加微信小程序開發大賽
> 本文件版本：v1（2026-10-22）｜後續 v2 補 API/Schema 細目
> 評分依據：2026 微信小程序開發大賽賽事規程（公開轉載版）四維度 30/30/20/20，報名前請以官方頁面為準

---

## 0. 一頁式定位（電梯簡報，30 秒版）

**「培華師生的一天，收在一個小程序裡。」**

校園裡每天發生四種高頻小事：**東西丟了找不到人、活動報名靠紙本或群裡接龍、今天午餐吃什麼、重要通知埋在群訊息裡**。這四件事各自只要 15 秒就能解決，但現在全校沒有任何一個地方能一次做完。

本項目把這四類校內資訊流做成**可互動、有狀態、能閉環**的產品：
誰丟了 → 誰撿到 → 誰認領完成；誰開了活動 → 誰報了名 → 名額滿了自動候補；這週菜單 → 大家評分 → 熱門菜式有數據支撐；學校發公告 → 學生真的看到、並能訂閱提醒。

**差異化一句話**：不是把學校官網搬進小程序，而是把「校園資訊流」變成「可互動的校內社區資產」——每一條內容都有狀態、有用戶、有數據回饋。

## 1. 三個真實痛點 → 解法 → 上線後可量化指標

| 痛點 | 現狀成本 | 我們的解法 | 上線後可出示的指標 |
|---|---|---|---|
| **失物招領** 東西丟了只能發群、問同學、去教務處問；撿到東西不知道交給誰 | 平均找回時間 1–3 天，多數直接放棄 | 發布（失物／拾獲）＋圖片＋地點＋分類；狀態機 `待認領 → 已認領 → 已完成`；**同分類＋同地點的智能推薦** | 發布數、認領成功率、平均認領時長 |
| **活動與社團報名** 紙本報名表／群裡接龍／班長統計，名額超賣、漏統計 | 每次活動主辦方要人工統計 1–2 小時 | 線上報名＋**名額樂觀鎖防超賣**＋候補隊列＋「我的報名」一鍵取消；開搶前**訂閱消息**提醒 | 報名轉化率、超賣事故數（目標 0）、候補自動補位數 |
| **菜單與公告資訊不對稱** 午餐吃什麼要問同學；校曆、臨時停課埋在群訊息 | 資訊碎片化，緊急通知觸達率低 | 當週菜單視圖＋菜式評分／點讚；公告分「緊急／置頂／校曆」；訂閱消息推緊急通告 | 菜單頁週活、評分數、公告觸達率 |

## 2. 功能地圖（P0 必做 / P1 加分 / P2 有時間再做）

### P0 — 沒有它就不算完成（考試及格線 ＋ 比賽最低門檻）
- 微信登入（`wx.login` → `code2Session` → 自簽 JWT）、我的頁（暱稱、班級、角色）
- **失物招領**：列表（篩選：類型／分類／狀態／關鍵字）、詳情、發布（含 1–3 張圖）、我的發布、狀態流轉
- **活動**：列表（進行中／即將開始／已結束）、詳情、報名／取消、我的報名
- **菜單**：當週視圖（週一至週五 × 午餐／小賣部）、菜式詳情、評分＋點讚
- **公告**：列表（置頂／緊急標記）、詳情
- 全域：骨架屏、空狀態、錯誤重試、下拉刷新

### P1 — 拉開分數的差異化
- 圖片直傳 COS（簽名上傳，不經過 API 伺服器）
- **失物智能匹配**（發布時自動推薦「可能是你的東西」）
- **訂閱消息**：認領通知、活動開搶提醒、緊急公告
- 舉報＋內容審核（`security.msgSecCheck` / `imgSecCheck`）
- 老師端 Web 管理後台：審核失物、發公告、排菜單、看活動報名名單
- 全站搜尋（失物／活動／公告聚合）

### P2 — 錦上添花（寫進 PPT 的「下一階段」）
- 熱門菜式排行榜、每週人氣 TOP3
- 深色模式、分享卡片（帶小程序碼）
- 收藏、消息中心
- 營運數據看板（DAU／發布量／報名量）

## 3. 競賽評分對標（2026 規程四維度）

> 規程原文：產品實用性 30、產品創新性 30、用戶體驗感 20、作品完整度 20；決賽另有現場匯報與答辯評價。
> 其中「產品實用性」明確包含 **AI 應用創新（與微信 AI 生態結合）** 與 **上線後用戶反饋數據（日活／月活）** 兩條判斷依據——這兩條直接決定我們要不要現在就啟動備案與上線。

| 維度（占比） | 評審其實在看什麼 | 我們的具體拿分動作 | 可出示的證據 |
|---|---|---|---|
| **產品實用性 30** | 痛點是否真實、場景是否明確、有沒有真實用戶數據、有沒有 AI 加值 | ① 開學前做一份校內問卷（≥100 份）證明四大痛點排序 ② P0 全部上線並在校內灰度一週，拿到 DAU／發布量 ③ **AI 智能匹配**：失物文字相似度＋課程表語義搜尋（自然語言「我星期三在圖書館掉了一個藍色水壺」） | 問卷結果圖、後台真實數據截圖、匹配命中率 |
| **產品創新性 30** | 主題是否避開紅海、模式是否獨創、差異化是否突出 | 市面上「校園失物」小程序多，「校園服務聚合」多，但**把「失物＋活動＋菜單＋公告」做成同一個身份體系下的校內閉環社區**很少見；差異化＝以「班級／社團」為單位的信任圈，而非開放式論壇 | 競品對比表（功能矩陣）、產品定位圖 |
| **用戶體驗感 20** | 交互是否易懂、設計是否規範統一、運行是否穩定 | ① 三大核心任務（報失物／報名活動／查菜單）**全部 ≤15 秒完成**，並在報告裡寫出點擊步數 ② 設計系統（color tokens＋8 個原子組件）保證視覺一致 ③ Skyline 手勢動效＋骨架屏，冷啟到首屏 <1.5s | 錄屏 GIF（15 秒完成任務）、設計規範頁、效能數據 |
| **作品完整度 20** | 資料是否齊全規範、論述是否清晰、產品價值是否說得明白 | ① 一頁式產品說明＋架構圖＋API 文檔＋測試報告＋運營方案 ② 小程序**正式上線並通過微信審核** ③ 老師端後台（證明不只是學生玩具） | 提交資料清單、上線版本 QR、審核通過截圖 |

**現場答辯準備（決賽另計分）**：準備三個必答題的 30 秒版本——「為什麼是這四件事」、「為什麼不用雲開發」、「如果全校 1200 人同時開搶活動名額，你的系統怎麼不崩」。

## 4. 六個亮點（含技術要點與預估工期）

| # | 亮點 | 技術要點 | 為什麼評審會記住 | 工期 |
|---|---|---|---|---|
| 1 | **失物智能匹配** | PostgreSQL `pg_trgm` 相似度 + 分類／地點／時間加權；發布時即時計算 Top3 推薦；可選接大模型做描述摘要與自然語言查詢 | 規程明列「AI 應用創新」，這是最容易講清楚、又能真跑起來的 AI 點 | 3 天 |
| 2 | **名額樂觀鎖＋候補隊列** | `UPDATE events SET signed_count = signed_count + 1 WHERE id = ? AND signed_count < capacity` 影響行數為 0 即滿員 → 自動進候補表；有人取消時按 `created_at` 補位並發訂閱消息 | 多數校園作品用「前端判斷有沒有滿」，這裡是真併發正確性，技術加分點 | 2 天 |
| 3 | **訂閱消息閉環** | `wx.requestSubscribeMessage` ＋ 後端 `subscribeMessage.send`；模板：認領成功、活動開搶、緊急公告 | 體現「微信生態內」而非「H5 套殼」 | 2 天 |
| 4 | **Skyline 手勢與過場** | Skyline + glass-easel、`worklet` 動畫、下拉刷新、卡片展開、骨架屏；`lazyCodeLoading` 分包 | 評審第一眼就是動效質感；Skyline 是新一代渲染引擎，技術敘事新 | 3 天（分散） |
| 5 | **老師端 Web 管理後台** | 同一個 Fastify 服務下的 `/admin` 路由 ＋ 簡單 JWT 角色；審核失物、發公告、排菜單、匯出報名名單 CSV | 「作品完整度」最有效的一擊：證明有雙邊運營設計 | 4 天 |
| 6 | **弱網與離線友好** | 本地快取（`wx.setStorage` TTL）、樂觀 UI、失敗重試與離線橫幅 | 澳門校園 Wi-Fi 經常不穩，是真實場景不是炫技 | 1.5 天 |

## 5. 技術架構（見 `docs/architecture.html`）

### 分層
```
[小程序端 Skyline]  頁面 / 自建組件庫 / 狀態管理 / 請求層(JWT+重試)
        │ HTTPS 443（已備案域名，微信合法域名白名單）
[接入層]  Caddy(自動 HTTPS) → Fastify 實例
[應用層]  認證 / 失物 / 活動 / 菜單 / 公告 / 上傳簽名 / 管理後台 / 定時任務
[數據層]  PostgreSQL(Prisma)  ·  Redis(可選：名額計數、限流)
[儲存層]  騰訊雲 COS + CDN（客戶端直傳，簽名授權）
[外部]    微信開放接口：code2Session / subscribeMessage / msgSecCheck
```

### 兩階段落地（Prisma 只改 `DATABASE_URL`）
| 階段 | 時間 | 資料庫 | API 部署 | 目的 |
|---|---|---|---|---|
| 階段一 | T+0 ~ T+2 週 | Supabase 免費層 Postgres | 本機 / DevTools 不校驗域名 | 全功能跑通、錄屏、內部測試 |
| 階段二 | T+3 ~ T+5 週 | 騰訊雲 Postgres（同 schema） | 騰訊雲輕量 + Docker + Caddy + 備案域名 | 真機上線、提審、收真實數據 |

> 報告寫法：這叫「同構遷移」——schema 與業務代碼零改動換庫，是架構合理性的證據，不是權宜之計。

## 7. 風險登記表

| 風險 | 影響 | 對策 | 負責時點 |
|---|---|---|---|
| ICP 備案延誤 | 真機上線不了 → 實用性分數歸零 | 今天啟動；備用方案：學校已備案域名子域、或真機開調試模式錄屏 | T+0 |
| Skyline 相容性（第三方組件庫不支援） | UI 進度受阻 | 不引入 Vant/TDesign，自建 8 個原子組件；每頁在模擬器驗證 | 持續 |
| 內容安全審核被拒（UGC 圖片／文字） | 上線卡住 | 發布前過 `msgSecCheck` / `imgSecCheck`，違規則攔截並提示 | 開發期 |
| 個人信息合規（班級、聯絡方式） | 審核與合規風險 | 最小化收集、聯絡方式可選「站內私信」、附隱私政策 | 設計期 |
| 單人開發工時不足 | P1 做不完 | P0 先完整可用；P1 按「亮點 2→1→3」順序砍 | 每週檢視 |
| 校內推廣不足 → 沒真實數據 | 實用性拿不到分 | 找 2 個班做種子用戶、設「首發尋找失物」活動、老師公告導流 | 上線週 |
